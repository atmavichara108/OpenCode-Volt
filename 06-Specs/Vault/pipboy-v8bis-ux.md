# Pip-Boy v8-BIS «КОМАНДНЫЙ ЦЕНТР» — UX-концепт

## 1. Диагноз (что не так у HUD/B и v7 views)

1. **Пассивность.** Дашборд показывает состояние, но не создаёт действие.
   Пользователь смотрит и уходит. Вопрос «что мне с этим делать?» остаётся.
2. **Информационная мозаика.** Виджеты по отдельности ясны, но их сводка
   не образует истории: почему P0 в DESIGN три недели? что блокирует
   SERPlux? кому адресовано «READY»? — это три разных взгляда, но не
   один разговор.
3. **Навигация списками.** 12 вкладок v7 = сканирование, а не движение.
   Искать глазами без цели — утомительно; deep-links не открывают
   «путь» между связанными вещами (карточка → её задача → её проект →
   её workspace).
4. **Пассивность к агентам.** Экосистема multi-agent, но UI молчит:
   агент не «работает над X», есть только owner=метка.
5. **Контекст связности.** В Pip-Boy нет «сейчас я работаю над …» —
   вся работа начинается с выбора view, а не с выбора задачи.

## 2. Ключевая идея: **«Задача — в центре, всё остальное — вокруг»**

Одна главная поверхность = **рабочий стол одной задачи (Task Deck)**.
Вместо дашборда-витрины Pip-Boy всегда показывает **один активный
фокус**: карточку + всё, что с ней связано, на одном экране. Остальная
экосистема видна через **док слева** (проекты + статусы) и **боковую
панель** (контекст выбранного: deps, task, evidence, capture-сигналы).

Переход между вещами — это не «смена view», а **движение по связям**:
кликнул карточку → вокруг неё раскрылось окружение (deps/blocks/tasks/
проект/владелец/сигналы); движение назад/вперёд — как в браузере
(history стек), `Esc` — возвращение к фокусу, `Tab` — следующий READY.

## 3. Экранная структура (4 зоны, одна работа)

```
+-----------------------------------------------------------------------+
| ЗАГОЛОВОК: Pip-Boy · фокус: ECO-029 · [◀ history] [▶] · R · P · ⌘K     |
+-------------+---------------------------------------------+-----------+
| ДОК (слева) |             ЦЕНТР (рабочий стол)             | КОНТЕКСТ  |
| проекты     |  ┌── ЗАГОЛОВОК ФОКУСА ─────────────────────┐ | (справа)  |
| + статусы   |  │ ECO-029 Replay budget в TUI   [P0][meta] │ | NEXT STEP |
| + свежие    |  │ ─ lifecycle: DESIGN → следующий: APPROVED │ | deps (n)  |
| capture     |  │ ─ Acceptance (коротко)                    │ | blocks(n) |
| сигналы     |  │ ─ Actions: [⧉ PROPOSAL][Workspace][dir]   │ | tasks (n) |
| + агенты    |  │ └─────────────────────────────────────────┘ | | artifacts |
| (кто может) |  │   [ДЕПС-ГРАФ]  [TASKS]  [EVIDENCE] [LIVE]   | | drift     |
| + timeline  |  │   карточки связанные, кликабельные         | | capture   |
+-------------+----------------------------------------------+-----------+
| СТАТУС-БАР: HEAD · DRIFT · SSE · горячие клавиши                      |
+---------------------------------------------------------------------+
```

## 4. Главные интерактивные механики

### 4.1 «Фокус» (главная единица работы)

- При старте Pip-Boy автоматически выбирает **первый READY** (P0/P1);
  вся левая/центральная/правая зоны строятся вокруг него.
- `Tab` = следующий READY (циклом по приоритету), `Shift+Tab` назад.
- Клик в доке/центре/справе = смена фокуса, история хранится
  (`Alt+←` назад по фокусам, как в браузере).

### 4.2 ДЕПС-ГРАФ как способ движения (не только как view)

- Центральный блок показывается для выбранной карточки: зависимость
  снизу, блокеры сверху, клики по чипам = смена фокуса.
- Транзитивные блокеры («держит N») — в панели контекста, клик —
  туда же.

### 4.3 Лента капчура как «входящие» (не витрина)

- Сигналы capture попадают в ленту «NEW», каждый сигнал имеет
  действие: [→ карточка] [→ проект] [→ открыть репо] [отложить].
- Непрочитанные — счётчик на доке; прочтение = локальная отметка
  (read-state в localStorage, как у skills).

### 4.4 Рабочие сессии (работа над фокусом)

- Кнопки в центре: **[Открыть workspace]** (tmux pb-<проект> через
  /action), **[Открыть в Neovim]** (карточка/артефакты), **[Новый
  decision-note]** (копирует текст proposal в буфер) — действие
  всегда на экране для текущего фокуса, не в отдельном view.

### 4.5 Live-пульс (SSE как часть разговора)

- Статус-бар всегда показывает живой HEAD/drift; событие SSE
  мягко подсвечивает затронутые виджеты (без toast-спама), счётчик
  «изменилось с последнего взгляда» на доке.

## 5. Эстетика (что сохраняем)

- CRT-тема, моноширинный шрифт, green/amber, scanlines — это
  идентичность Fallout, её не меняем.
- Плотность: меньше одновременно (док 240px, центр 70%, справа 300px);
  пустое пространство дышит; ничего не мигает без причины.
- Анимации: только смысловые (смена фокуса — 150ms fade, подсветка
  соседей графа).

## 6. Навигация (keyboard-first)

| Клавиша | Действие |
|---------|----------|
| `Tab` / `Shift+Tab` | следующий/предыдущий READY |
| `1..4` | док: проекты (1: vault, 2: SERPlux, 3: dotfiles, 4: dv-hub) |
| `Space` | раскрыть/свернуть раздел контекста |
| `Enter` | действие по умолчанию фокуса (proposal/verify) |
| `←/→` | история фокусов (назад/вперёд) |
| `?` | шпаргалка клавиш (overlay) |
| `Ctrl+K` | палитра (переносится из v7) |
| `Esc` | закрыть оверлей / вернуться к фокусу |

## 7. Что остаётся от v7 (не выбрасываем)

- Backend полностью: registry/observer/actions/pipboy host/SSE/custom
  tools. v8-BIS = новый **фронт-сло́й** на тех же данных.
- Панель карточки, palette, inspector, compact, export, rofi-запуск —
  переиспользуются.
- KANBAN/DEPS/ACCEPTANCE не исчезают — они становятся «режимами центра»
  для выбранного фокуса (например KANBAN фокусируется на проекте фокуса).

## 8. Прототип

Кликабельный мокап с реальными данными (registry+snapshot через тот же
pipboy host): `tools/ecosystem-map/v8bis.html` — отдельный файл, main
index.html не трогается до утверждения концепта. Все данные живые:
фокус, док, контекст-панель, TAB-цикл READY, депс-движение.

## 9. Милое: не входит в v8-BIS (за горизонт)

- timeline/heatmap активности (после event-log ECO-017),
- интеграция capture-mark (пометить прочитанным в Telegram),
- drag&drop карточек (запрещено read-only; только proposals).
