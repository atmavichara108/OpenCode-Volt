## Требования к документам

### `docs/roadmap-2.0.md`

Оформить техдолг v2.0 с двумя обязательными разделами: `ПРОДУКТ` и
`АРХИТЕКТУРА`. В разделе `ПРОДУКТ` явно указать: Deep-режим разметки, удаление
legacy `label_mode`, автоматизацию эталона, ротацию backup, watchdog зависших
прогонов, уведомления, мониторинг стоимости LLM, известные проблемы качества
qwen-plus и низкое покрытие эталоном, geo dedup, сохранив остальной roadmap.

В `АРХИТЕКТУРА` указать P1 для глобального `domain_labels` без `client_id`,
customer-specific предположений `migrate.py` и нормализации test-count к 262;
P0 global run status/lock, daemon jobs и credentials только для shared instance.

### `CHANGELOG.md`, rollback, acceptance

Changelog — Keep a Changelog, `[1.0.0] - 2026-08-17`, только подтверждённые
историей изменения. Rollback описывает только реально поддержанные git,
Compose, `deploy.sh`, `backup_db.sh` и пути БД; restore не выдумывать.
Acceptance checklist явно разделяет подтверждённое и непроверенное для 262
тестов, `label_only`, отчёта, geo dedup и эталона.

README должен отражать продукт, структуру и 262 теста; код и тесты не менять.
В progress добавить: v1.0 зафиксирована, maintenance-режим, разработка
смещается на Overture.
