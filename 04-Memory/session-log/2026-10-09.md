# Session-log 2026-10-09 — разрешение инцидента justwoker (T-168)

## Итог
Инцидент justwoker (сессия 2026-10-08/09) **разрешён**. Опус вернулся и работает;
стрим-регрессия шлюза ушла; локальный шим стал **опциональным** мостом.

## Факты
- **Опус работает.** Прямой curl к `api.justwoker.icu`, `claude-opus-4-8` →
  HTTP 200 за ~28с, реальный ответ. End-to-end через шим (`127.0.0.1:8787`,
  `stream:true`) — 3/3 успешных, реальный контент; журнал шима: циклы ~27–30с
  («200 (synthesized SSE, blocks=1..2)») вместо 15-минутных висняков.
- **Стрим-регрессия ушла.** Апстрим на `stream:true` снова отдаёт полный
  Anthropic SSE: `message_start → ping → content_block_start →
  content_block_delta → content_block_stop → message_delta → message_stop`
  (проверено 2026-10-09). Первопричина существования шима исчезла.
- **TimeoutError — три слоя, все разобраны:**
  1. краш шима при отмене клиента — фикс crash-guard `dee6f15`;
  2. фантомный фикс `headersTimeout:0` — Bun fetch игнорирует эти опции
     (серверные); реальный лимит — клиентский socket-idle
     `BUN_CONFIG_HTTP_IDLE_TIMEOUT`=300с (bun #16682); фикс `timeout: false`
     в fetch, коммит `49d8d74`, потолок 600→900с;
  3. висняки ровно 900с (08:44 / 08:59 / 09:14 2026-10-09) — мёртвый канал
     у дистрибьютора провайдера (внешнее), канал ожил ~09:2x.
- **amd-radeon:** 503 «no_available_workers (all circuits open or unhealthy)» —
  провайдерский предохранитель воркеров, сам восстановился; к нашим изменениям
  не относится (в конфиге трогались только блоки justwoker). «Гейта обновления
  моделей по провайдерам» в конфиге не найдено.
