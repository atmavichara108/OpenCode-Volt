## Факты (вечер: большой payload)

- **Корень висняков больших payload — прямое соединение с Cloudflare, не шим
  и не Bun-код.** Матрица соединений (тело 796KB): напрямую к CF — `http=000`
  >45с; через локальный прокси `127.0.0.1:10809` — 200 за ~26с; малое тело
  напрямую — 200 за 4.6с. Классический MTU/mss blackhole: большие сегменты
  не доходят. Все прежние «успешные прямые тесты» шли через прокси
  (curl подхватывал env-переменные), а шим в systemd шёл напрямую.
- **Bun-овый сетевой стек сломан на больших upload'ах независимо от варианта**
  (репро 796KB): `node:https` HANG во всех вариантах записи (write+end /
  end(body) / chunks+drain / keepAlive:false Agent), `bun fetch` TimeoutError;
  curl с тем же телом — 200 за ~9с.
- **Фикс — шим v4 (curl-транспорт), dotfiles main=`026213a`:**
  (1) `openRaw`: `node:https` → curl subprocess (spawn; тело в stdin;
  заголовки из stdout `-i`, с пропуском CONNECT-туннеля прокси и 1xx);
  (2) `SHIM_PROXY` env (default `http://127.0.0.1:10809`, пусто = напрямую);
  (3) юнит: `HANG_MS=30000`, `FORWARD_RETRIES=1`; прокси локальный —
  совместим с `IPAddressAllow=localhost`;
  (4) исчерпание stream-ретраев по hang → fallback на non-stream (вместо
  ошибки клиенту): stream:true у апстрима периодически висит без байтов,
  non-stream стабильно работает.
- **End-to-end evidence (production 8787):** 796KB → **200 за 12с**;
  stream:true → **200 за 4.7с, живые content_block-дельты**; бенч против
  заглушек: (a) live 39мс, (c) hang-retry 6.5с, (d) fallback — зелёные;
  `bun build` exit 0.
- **Ход работы:** v3 (node:https agent:false) написан и «зелёный» на бенче
  со стабами, но висел на реальном большом payload; диагностический цикл
  (репро трёх вариантов записи → граница бага → матрица прокси) привёл к
  настоящему root cause. Subagent meta недоступен (4 падения: step limit,
  429, Agent not found) — операционно доводил сам дирижёр по явному слову
  Рудры (scope: инфра шима, не код приложений).

## Факты (утро)

- **Опус работает.** Прямой curl к `api.justwoker.icu`, `claude-opus-4-8` →
  HTTP 200 за ~28с, реальный ответ. End-to-end через шим (`127.0.0.1:8787`,
  `stream:true`) — 3/3 успешных, реальный контент; журнал шима: циклы ~27–30с
  («200 (synthesized SSE, blocks=1..2)») вместо 15-минутных висняков.
- **Стрим-регрессия ушла.** Апстрим на `stream:true` снова отдаёт полный
  Anthropic SSE: `message_start → ping → content_block_start →
  content_block_delta → content_block_stop → message_delta → message_stop`
  (проверено 2026-10-09). Первопричина существования шима исчезла.
- **TimeoutError — три слоя, все разобраны:**
  1. краш шима при отмене клиента — фикс crash-guard `dee6f15`;
  2. фантомный фикс `headersTimeout:0` — Bun fetch игнорирует эти опции
     (серверные); реальный лимит — клиентский socket-idle
     `BUN_CONFIG_HTTP_IDLE_TIMEOUT`=300с (bun #16682); фикс `timeout: false`
     в fetch, коммит `49d8d74`, потолок 600→900с;
  3. висняки ровно 900с (08:44 / 08:59 / 09:14 2026-10-09) — мёртвый канал
     у дистрибьютора провайдера (внешнее), канал ожил ~09:2x.
- **amd-radeon:** 503 «no_available_workers (all circuits open or unhealthy)» —
  провайдерский предохранитель воркеров, сам восстановился; к нашим изменениям
  не относится (в конфиге трогались только блоки justwoker). «Гейта обновления
  моделей по провайдерам» в конфиге не найдено.
