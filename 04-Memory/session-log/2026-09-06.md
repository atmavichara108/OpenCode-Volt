# Сессия 2026-09-06 — LinaliAPI → OpenCode

## Задача
Rudra захотел подключить нового провайдера **LinaliAPI** (linaliapi.com) к OpenCode, чтобы переключать модели из `/models` интерфейса. `/connect` не дал провайдера в списке.

## Исследование
- Страница `dashboard/connect` — SPA, вытащены гайды из `dashboard/integrations.js`: LinaliAPI — OpenAI/Anthropic-совместимый шлюз, `baseURL https://api.linaliapi.com/v1`, ключи `sk-ant-*`, официальный шаблон для OpenCode (`@ai-sdk/openai-compatible`), verify `opencode run`.
- Список моделей получен от пользователя (ID с вендорными префиксами: `anthropic/...`, `openai/...`, `z-ai/...`, `deepseek/...`, `google/...`).

## Диагноз (3 причины)
1. **`/connect` сохраняет только ключ** в `~/.local/share/opencode/auth.json`; провайдера нужно описывать в конфиге (подтверждено https://opencode.ai/docs/providers/). LinaliAPI нет в models.dev → без конфиг-блока в `/models` пусто.
2. **Опечатка ID:** в auth.json ключ сохранён как `linalinapi` (лишняя «n»).
3. Глобальный конфиг на этой машине — **`opencode.jsonc`**, не `.json` (файл `.json` отсутствует; `[проверить]` из 01-Reference/global-config.md подтверждён).

## Исполнение (route decision)
- Named capability `meta` в сессии не зарегистрирован → исполнитель **`general`** с явным scope/acceptance по прямому указанию пользователя («ты оркестратор, используй субагентов»). Librarian прямых правок конфигов не делал.
- Субагент 1: проектный конфиг волта — `provider.linaliapi` (5 моделей) + permission-allow `~/.config/opencode/**` в external_directory (позиция критична: после `*` deny, до секретных deny — last-match-wins). **DONE**.
- auth.json rename `linalinapi→linaliapi`: субагент **BLOCKED** (mv-запись в ~/.local/share/opencode отклонена), librarian bash **BLOCKED** (запись в этот путь режется пермишенами, загруженными при старте; чтение ранее шло через ask). Эскалация пользователю: jq-однострочник — **выполнен пользователем**, после рестарта #1 модели подтянулись.
- Субагент 2: глобальный `~/.config/opencode/opencode.jsonc` — `provider.linaliapi`, **6 моделей** (добавлен `openai/gpt-5.6-luna` по запросу): claude-opus-5, gpt-5.6-sol, gpt-5.6-luna, gemini-3.8-flash, glm-5.3, deepseek-v4-pro. `apiKey` в options не хардкодится — подтягивается из auth.json по совпадению ID. `jq empty` VALID. **DONE**.
- Субагент 3: из проектного конфига волта секция `provider` удалена (SSOT — источник теперь глобальный), external_directory allow сохранён. **DONE**.

## Подтверждённые факты (→ facts.md)
- `/connect` = только auth; кастомный провайдер = config-блок; ID провайдера в конфиге должен совпадать с ключом в auth.json.
- Глобальный конфиг здесь: `opencode.jsonc`.
- external_directory: побеждает последнее совпавшее правило.
- Permission-границы сессии фиксируются при старте opencode; запись в `~/.local/share/opencode/*` из агентской сессии заблокирована (в отличие от чтения, которое идёт через ask).

## Статус / остаток
- ⏳ После рестарта #2: `/models` должен показывать LinaliAPI из глобального конфига во всех проектах; тестовое сообщение на модели `linaliapi/...` (если 401 — проверить, что jq-команда над auth.json выполнена).
- ⏳ Опционально: задокументировать провайдера в [[01-Reference/providers]] (там сейчас «4 провайдера» — устарело).
- Провайдер-блок пока только в `~/.config/opencode/opencode.jsonc`, не в dotfiles-каноне (`~/dotfiles/opencode-global/`) — при следующей ревизии dotfiles перенести, иначе потеряется при restow.
