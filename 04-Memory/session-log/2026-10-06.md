  recommendation исполнителя (а) учтена, решение не делегировано.

### Переносимые паттерны
- **Полный цикл делегации:** аудит → дизайн-вопросы (развилки, не открытые)
  → route decision по схеме → handoff-промт → peer-подтверждение → исполнение
  → git-evidence → независимая верификация → append-only закрытие. Отработал
  end-to-end за 2 дня, годится как эталон для T-157 и подобных.
- **Свежесть ТЗ перед dispatch:** ре-верификация контракта на живом эндпоинте
  (версии выросли, контракт жив) спасла от исполнения по устаревшим фактам;
  конкретные PID/версии в промты не класть — только механизмы (`pgrep`, порты).
- **Ответный канал git-дерево** — надёжнее live-пуша: письмо может потеряться
  при рестарте сервера, коммит нет.
- **Верификация через /proc/<pid>/cgroup** — канонический способ доказать
  ownership порта юнитом (ss pid + cgroup, а не «поверь на слово»).
