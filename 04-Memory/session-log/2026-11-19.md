### Корневая причина 451 в шлюзе new-api (гео-блок NVIDIA) — устранена

- Симптом: free-vision через шлюз → HTTP 451 с **пустым телом**; в логе `bad response status code 451, body:`; ретраи шли в тот же канал (лог шлюза: 8->35->35->35).
- Локализация: mock-перехват показал, что шлюз шлёт **правильный** путь `POST /v1/chat/completions` (фикс двойного `/v1` работает), тело/заголовки корректны, ключ совпадает с живым (sha256[:12]=`fa251c959e57`, `nvapi-pvgG…`, 70 симв., у всех 7 nvidia-каналов).
- Корень: **прямое соединение с нашего IP блокируется edge NVIDIA** (`server: awselb/2.0`, `content-length: 0`) → 451; через прокси тот же запрос → 200. Гео-блок только у NVIDIA: openrouter/vercel/mistral/amd при прямом соединении доходят до своих серверов (403 cloudflare / 401 Vercel / 401 cloudflare / 401 nginx).
- Механизм: процесс шлюза запускался только с `ALL_PROXY=socks5h://127.0.0.1:10808`, а Go (new-api) читает лишь `HTTP_PROXY`/`HTTPS_PROXY` → релей шёл напрямую. - Проверено и отброшено: per-channel `channels.other={"proxy":...}` в new-api **не читается** (проба → снова 451).
- Фикс (применён): в `~/.config/systemd/user/new-api.service` добавлены `Environment=HTTP_PROXY=http://127.0.0.1:10809`, `Environment=HTTPS_PROXY=http://127.0.0.1:10809`, `Environment=NO_PROXY=localhost,127.0.0.1,::1`; `daemon-reload` + `restart` (бэкап юнита: `new-api.service.bak-20261119-0430`).
