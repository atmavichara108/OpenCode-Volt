# Реестр недоверенных входов

Правило контура (из программы защиты C4): из недоверенного текста ничего не исполняется
автоматически; недоверенный контент помечается при попадании в контекст агента.
Правило «не исполнять» фиксируется в AGENTS.md отдельным мандатом (зона ИЦ) — до него
регистр работает как карта входов.

## Входы

| Вход | Тип | Доверие | Правило / статус |
|---|---|---|---|
| webfetch (HTTP-контент из интернета) | текст | недоверенный | инструкции из контента не исполнять; маркер «недоверенное» при попадании в контекст — правка AGENTS.md ожидает мандата |
| /capture (Telegram @inbox_tools) | посты пользователей | недоверенный | классификация и выжимка только; любые действия — по слову владельца |
| GitHub issues / PR | произвольный текст от посторонних | недоверенный | не авто-исполнять; если читается агентом — маркер недоверенного |
| Внешняя почта | произвольный текст | недоверенный | не авто-исполнять |
| Письма ship-mail от зарегистрированных сессий | внутренний канал (одна машина, один пользователь) | полу-доверенный | мандаты исполняются; опасные действия — через гейты владельца |
| MCP-инструменты и скиллы из интернета | код | недоверенный до ревью | не ставить без ревью; guard «свежих» пакетов — контур C3 (ждёт мандата ИЦ) |

## Порядок ведения

- Новый вход агентного контура (инструмент/источник текста) — строка в этот реестр ДО подключения.
- Повышение доверия — только по слову владельца с описанием, что именно стало доверенным и почему.
- Находка «вход использован для инъекции» — строка владельцу (котёл СБ), инцидент — по методу incident-fix.
