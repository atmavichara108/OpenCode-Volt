# 98-Temporary — буфер для экстракции

> **Назначение:** временное хранилище сырых файлов (выгрузки, дампы, вложения),
> которые пользователь присылает для **экстракции** знания в волт. После обработки
> файлы подлежат удалению. Не часть OKF-бандла, а сервисная область intake.

## Допустимое содержимое
- Сырые выгрузки (Telegram-экспорты, логи, дампы чатов/документов).
- Вложения от пользователя (PDF, txt, md-фрагменты), переданные на разбор.
- Промежуточные артефакты пайплайна `/capture` и аналогичных команд.

Недопустимо: код приложений, готовые методы/карточки, конфиги агентов, заметки —
всё это живёт в `02-Methods/`, `03-Projects/`, `01-Reference/` или `99-Inbox/`.

## Workflow: intake → extraction → destination → deletion
1. **Intake.** Пользователь кладёт файл сюда (или librarian/субагент сохраняет
   вывод команды). Имя файла — осмысленное + дата, напр. `tg-export-distill-2026-08-03.txt`.
2. **Extraction.** Агент читает файл, дистиллирует знание (факты → `01-Reference/`,
   приём → `02-Methods/`, контекст проекта → `03-Projects/`, сессия → `04-Memory/`).
3. **Destination in vault.** Результат оформляется в соответствующий каталог волта
   с правильным `type:` в frontmatter; в `99-Inbox.md` при необходимости добавляется
   строка-источник.
4. **Deletion.** После подтверждения, что знание осело в волте, исходный файл из
   `98-Temporary/` **удаляется**. Каталог должен оставаться пустым в стационаре.

## Правила
- **Не источник правды.** Файлы здесь — сырьё, а не canon. Истина — в `01-Reference/`,
  `02-Methods/`, `03-Projects/`. Если содержимое противоречит волту, прав волт.
- **Не смешивать с `99-Inbox/`.** `99-Inbox.md` — буфер коротких заметок-идей
  одной строкой; `98-Temporary/` — крупные file-based артефакты на экстракцию.
  Inbox перетекает в методы/карточки через `/inbox`; Temporary — через экстракцию
  с последующим удалением оригинала.
- **Эфемерность.** Файлы не индексируются в `00-INDEX.md` как контент; каталог
  существует в дереве как сервисная зона intake.
