Команда: /audit $ARGUMENTS

Параллельный аудит проектов (P6 #32): вместо последовательного обхода `git pull`
каждый проект обследуется **отдельным эксплор-субагентом**, результаты сводятся
в единый дашборд.

## Порядок

1. **Собери список проектов.** Если `$1` указан — только `03-Projects/$1.md`.
   Иначе — все `.md` в `03-Projects/`, кроме `vault.md`.

2. **Fan-out.** Для каждого проекта запусти независимого эксплор-субагента
   `task(agent=explore)` со строгим read-only scope. Все субагенты стартуют
   параллельно (один `task`-вызов со списком), каждый получает:
   - путь карточки `03-Projects/<name>.md` (извлечь из неё `repo:` путь);
   - задание: `cd <repo>` → `git remote -v`, `git log --oneline -5`,
     `ls .opencode/` (агенты/команды/плагины), сверить с карточкой волта;
   - запрет на мутацию: только read-команды (`git status`, `git log`,
     `git remote -v`, `ls`, `cat`, `grep`), **никаких** `git pull`/`edit`.

3. **Сборка.** Собери вывод субагентов в сводную таблицу:

   | Проект | Путь | Последний коммит | Агенты/команды .opencode | Статус карточки |
   |--------|------|-----------------|--------------------------|-----------------|

4. **Сверка и действия.** Для каждого проекта пометь:
   - карточка актуальна («✅ свежо») или устарела (нет агента/команды,
     сменился remote, история ушла вперёд);
   - если устарела — предложи конкретные правки карточки. **Применяй только
     после подтверждения пользователя.**

## Почему fan-out
Эксплор по проектам — независимые read-only задачи: их параллельное
выполнение сокращает аудит с N последовательных git-обходов до одного
раунда. Контракт субагента фиксирует read-only границу (no pull, no edit),
acceptance — только снять факты, вердикт остаётся за librarian.
