Команда: /canonize $ARGUMENTS

Аргумент — слово владельца или ссылка на него.

## Жёсткие правила
- **Слово владельца — единственная авторизация.** Сохраняется дословно
  (`basis: quoted`); домыслы запрещены. Неоднозначность → вопрос владельцу,
  не трактовка молча.
- **`general` не является silent fallback.** Неизвестный маршрут = `UNROUTABLE`.
- Ссылки: [[02-Methods/capability-routing]], [[04-Memory/peer-registry]],
  [[01-Policies/skill-taxonomy]], [[02-Methods/ministry-calibration]],
  [[01-Policies/decisions-registry]].

## Шаги

1. **Сохрани формулировку владельца ДОСЛОВНО** (quoted), не пересказывая.
   Определи тип знания: политика (`01-Policies/`), метод (`02-Methods/`),
   факт (`04-Memory/facts.md`), терминология/таксономия.

2. **Проверь конфликт с существующим каноном** — grep по соответствующему
   слою (политики, методы, факты, таксономия). При конфликте:
   остановись и покажи владельцу delta как вопрос. Не переписывай канон
   по своему решению.

3. **Запись выполняет named executor**, не командир: `meta` — для агентной
   инфраструктуры; профильное ведомство — для его зоны; librarian-координатор —
   для волта. Сам канон молча не пишется. Маршрут — по
   [[02-Methods/capability-routing]]; нет исполнителя → `UNROUTABLE`.

4. **Детерминированные проверки:** `garbage-guard check-text` на изменённом
   файле, битые викилинки — `/verify`, коммит в `task/*`-ветку (не в `main`).

5. **Если решение образует правило поведения** — строка в
   [[01-Policies/decisions-registry]] с `basis: quoted` (дословная цитата
   владельца, не пересказ).

## Выход
Путь файла + hash/коммит + одна строка: что именно канонизировано.
