# Таксономия навыков

## Слово владельца (дословно, 2026-10-19)

> «навык - простое одно-двухсложное действие, решающее одну задачу за раз;
> сверхнавык состоит уже из нескольких действий образующих более сложное
> исполнение, может собироться из нескольких навыков при условии успешного
> решения более комплекстных задач; метанавыки - любой сложности действия
> выполняемые фоново или програмно без апрува капитана, способны
> эволюционировать в ультра навыки»

## Канон уровней

| Уровень | Определение | Критерий распознавания | Пример |
|---|---|---|---|
| **Навык** | Простое одно-двухсложное действие, решающее одну задачу за раз | Атомарно: одна цель, результат проверяется сразу, не требует сборки из других навыков | отправить письмо по реестру; сверка адреса; коммит памяти; факт-сверка одной строки |
| **Сверхнавык** | Несколько действий, образующих более сложное исполнение; собирается из нескольких навыков **при условии успешного решения более комплексных задач** | Составной: несколько навыков в связке, у каждого свой результат, есть общий DoD | «модернизация и создание ведомств» (включает [[02-Methods/ministry-calibration]]); «приёмка исследования» (факт-сверка → verifier → merge → реестр); «выкладка волта» |
| **Метанавык** | Любой сложности действие, выполняемое **фоново или программно без апрува капитана** | Работает без ручного запуска и без подтверждения; сам себя поддерживает; не требует владельца в цикле | мониторинг проектов; гейты pre-commit; флаш памяти; реестры/route-log; tg-guard + OCR |
| **Ультранавык** | Эволюция метанавыка — высшая форма | Самоподдерживающийся и самообучающийся контур: сам решает, что ловить/калибровать, без участия капитана и без ручного запуска | рабочая трактовка (определение владельцем отдельно не дано) |

**Атрибуция:** уровень определяется **способом исполнения** (ручное/фоновое),
а **не сложностью** — метанавык может быть технически сложнее сверхнавыка.
«Без апрува капитана» относится к исполнению фонового контура; расширение
scope, новые внешние действия и необратимые операции по-прежнему требуют слова
владельца ([[AGENTS]] контракт).

## Маппинг способностей ЦУ (2026-10-19)

**Навыки:** отправить письмо (letter.sh по реестру), сверка адреса/реестра,
факт-сверка одного утверждения, коммит памяти, обновление строки TASKS.

**Сверхнавыки:**
- «Модернизация и создание ведомств» — 6-шаговая калибровка
  ([[02-Methods/ministry-calibration]]).
- «Приёмка пакета ведомства» — факт-сверка → независимый verifier → merge/реестр.
- «Выкладка волта» — pre-checks → commit → tree-cop → push/merge.
- «Межведомственная координация» — реестр адресов → постановка → своевременная
  доставка → evidence → закрытие.

**Метанавыки:** мониторинг проектов (карточки ↔ git), флаш памяти, pre-commit
гейты, реестры и route-log, decision-queue, tg-guard+OCR, калибровка адресов
при смене сессий.

**Цель-ультранавык:** контуры, которые сами решают, что калибровать и что
фиксировать, без ручного запуска (каждый метанавык рассматривается как
кандидат на эволюцию).

## Связь с командами

Пользовательские точки входа — slash-команды, каждая — вход в навык или
сверхнавык (см. `01-Reference/commands.md` и `.opencode/command/`). Команда
не создаёт новый уровень: она лишь вызывает уже канонизированный навык.
