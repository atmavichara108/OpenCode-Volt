# Р-028 — ship-mail — канонический транспорт писем Корабля; старый канал — в резерв, затем снятие.** Слово владельца (basis: quoted): «у служителя обсидиан, уас, дв-хаба проблема с приёмкой писем

## Статус
действует, внедрение — мандаты ИС/УАС

## Суть решения
дв сделал пилот новой системы писем. проверить и если он лучше то применить его для всех, старый способ убрать». Проверка ЦУ: пилот Смотрителя ДВ-Хаба (dv-hub, scripts/ship-mail.sh + tests, спека docs/specs/ship-mail-pilot.md) — тесты 7/7 + живой дым (доставка/show/ack/дубль-отказ/реестровая адресация) — PASS. Почему лучше: доставка = атомарная запись файла (ноль ходов модели, ноль демонов, ноль журнала — файлы и есть истина), поэтому классы поломок старого канала («ложное sent», потерянные письма, отказ адресату без агента, цена хода модели на письмо) невозможны по построению. Канон: (1) транспорт писем Корабля — ship-mail; (2) адресация — только peer-registry (INC-18, как и было); (3) правило всех сессий: первый шаг хода — inbox своего id, отработал — ack; (4) письмо = OKF-файл, читается владельцем как обычный файл; (5) старый канал (letter.sh/run-инжект) — резерв для аврала и релея владельца, затем снятие по stabilization; (6) инструмент переезжает из dv-hub/scripts в общую зону (dotfiles) — ИС; протокол в стандарты — УАС. Верификация: ЦУ 2026-10-24 (тесты + живой дым), artifact: 06-Audits/2026-10-24-ship-mail-verification.md.
