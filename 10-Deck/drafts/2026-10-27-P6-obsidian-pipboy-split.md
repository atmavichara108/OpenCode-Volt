# P-6. Разделение Obsidian ↔ Пип-Бой

## Кто есть кто (одно предложение на каждый)

- **Обсидиан** — устав, канон и архив корабля: долговременная память
  (решения, реестры, досье, Deck-проекции `ssot: false`).
- **Пип-Бой** — живой экран рубки: состояние сейчас, события потоком,
  кнопки действий (через Ворота).

## Правило единого состояния (без двойных записей)

1. Живое состояние — только из opencode API и диска (маппинг P-3 §2).
   Обсидиан runtime-состояние **не хранит**.
2. Пип-Бой в заметки **не пишет** — согласовано с P-3 §3: единственный
   путь записи — Рубка-контроллер (Ворота / белый список); экран никогда
   не пишет сам.
3. Заметку меняет только агент по канону волта; Пип-Бой не обходится.
4. Проекция (`ssot: false`) живёт в Обсидиане и генераторах; живой экран
   не дублирует проекции, а читает те же источники.

## Deep-links (текстовые схемы, без плагинов)

- **Тайл → канон:** `obsidian://open?vault=OpenCode-Vault&file=<путь>` —
  кнопка «что это» на приборе открывает его заметку (квест → `Q-*`,
  решение → карточка ADR-032, ведомство → карточка реестра).
- **Заметка → живое:** `pipboy://<module>/<tile>` — из заметки канона
  ссылка «смотреть живьём» на соответствующий прибор; схема фиксируется
  здесь, изменение схемы — правка P-6 через фиксацию ЦУ.
- Смысл: тайл показывает живое, заметка объясняет почему; клик с тайла —
  в устав, ссылка из устава — на пульт.

## Запреты (потолки из досье, не темы для спора)

- Пип-Бой не редактирует канон и не «улучшает» заметки.
- Обсидиан не пытается быть живым — уточнение (правка ИЦ): **Bases-виды
  разрешены как read-only проекция** (deck.md с живыми таблицами из
  frontmatter — законный вид); запрет — про **хранение runtime-состояния
  и кнопки-действия** в Обсидиане. Deck канону не противоречит.
- Общие данные (квесты, решения, аварии) живут в одном месте — реестрах;
  ни Обсидиан, ни Пип-Бой не создают своей копии правды.
