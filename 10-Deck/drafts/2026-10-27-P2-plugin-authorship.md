## Зоны кода

| Где | Что |
|---|---|
| `~/Projects/OpenCode-Vault/.obsidian/plugins/**` | плагины Корабля (живые) |
| `~/Projects/OpenCode-Vault-plugins-sandbox/**` | песочница: разработка и тесты до гейта |
| проект-клиент SerO (напр. TradingMind) | **НЕ в правах агента**: плагины проекта пишет Служитель (или профиль SerO); зона добавляется agent'у только правкой через УАС — «зона в тексте ≠ зона в правах» (урок ИЦ) |
| dotfiles | только сам агентский файл (зона meta/ИЦ), не код плагинов |

Код Корабля (dotfiles, dv-hub, tools, ~/.config/opencode) для агента —
read-only. Секреты — never. npm-зависимости — только в package.json
плагина, системно ничего.

## Как принимается (замкнуто на P-1/P-4)

1. Задача агенту ставит Служитель с явным scope; агент не расширяет.
2. Готовый плагин проходит **P-1** (гейты G1–G8, включая транзитивные
   зависимости) в песочнице.
3. Приёмка — по **P-4**: G1 самопроверка (real build + smoke) → G2
   независимый verifier → G3 глаза владельца (для Корабля обязательно —
   плагин есть код у источника правды) → G4 ship-порядок ЦУ → G5
   фиксация. Для SerO-проектов G3-G4 — через владельца проекта.
4. Плагин — версии, git-контур, тег; пин в community-plugins.json;
   обновление пина = новый прогон P-1 (канон G8).

## Стандарт отчёта

Агент отчитывается по-русски, без кода в чате (S0-А5): что сделано
(файлы), как проверено (сборка/smoke), что осталось. Вердикт приёмки —
не себе: Служителю/verifier'у.
