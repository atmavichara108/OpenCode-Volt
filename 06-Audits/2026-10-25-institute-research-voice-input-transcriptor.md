# Исследование: голосовой ввод — путь внедрения Transcriptor (кандидат №1)

- **Дата:** 2026-10-25 (веб-верификация 2026-10-25/26)
- **Исполнитель:** Институт Передовых Технологий (ИПТ)
- **Мандат:** ИЦ voice-input-20261025, уточнение-2 от 2026-10-25
- **Статус:** исследование завершено, awaiting независимый verifier; гейт — приёмка ЦУ
- **Гейт:** в main не мержится; push только ветки task/institute-voice-20261025

## Провена

1. Слово владельца (basis quoted, 2026-10-25): «чтобы реализовать задуманное,
   мне потребуется голосовой ввод… это значительно упростит и ускорит работу».
2. Мандат ИЦ voice-input-20261025 + уточнение-2 (2026-10-25): кандидат №1 —
   github.com/leoerdman/Voice-Transcriptor; платные API не исключены
   (уточнение-2 отменяет прежнее «только локальное»; назван внешний ключ).
3. Протокол: ИПТ (исследование) → Лаба (пилот) → ИЦ (внедрение).
   Бюджет инфраструктуры: ноль; сборка из исходников бесплатна.
4. Референты: И-54/И-55 PolterType (поле ввода как поверхность автоматизации);
   Лаба tools/lab-l9 (пилот-площадка, GGUF/llama.cpp-экосистема);
   отказ от автозамены по пробелу (нажатие пробела не должно триггерить
   вставку/апрув — вставка только по хоткею/финализации).
5. Среда: Manjaro, X11, Qtile; 16 ГБ RAM (измерено 2026-10-26: total 15 Gi,
   available 8,2 Gi); цель — русский текст в ЛЮБОЕ поле; целевое — поле
   ввода opencode TUI (alacritty).

## 2. Шесть пунктов мандата — вердикты

### П.1 Сборка/зависимости на Manjaro

- Версии: Node 22.12.0 (.nvmrc), Python 3.12.13 (.python-version). В репозиториях
  Arch/Manjaro системные node/python могут быть новее 22.12/3.12 — риск несовпадения.
  Надёжный путь: точные версии через nvm/fnm (node) и uv/pyenv (python),
  системные пакеты — только для общих зависимостей.
- Ставит владелец pacman'ом (разово, без установки агентом):
  `sudo pacman -S --needed base-devel git ffmpeg xdotool wmctrl zenity alacritty`
  плюс менеджер версий: `sudo pacman -S --needed fnm uv` (или nvm по желанию).
- Готовых бинарников нет (Releases пусто) — только сборка из исходников:
  npm ci в frontend и desktop, потом dev-режим (`npm --prefix desktop run dev`)
  или сборка AppImage/deb-артефактов через desktop-скрипты.
- Цена сборки Electron (оценка): node_modules двух пакетов ~0,7–1,5 ГБ на диске,
  кэш Electron ~0,3 ГБ, первая сборка 5–15 мин, пик RAM при сборке ~2 ГБ.
  Итог: ~2–3 ГБ диска, на 8,2 Ги свободной RAM — безопасно.
- ffmpeg обязателен (извлечение аудиодорожки); xdotool/wmctrl/zenity — Linux-зависимости
  вставки и диалогов (в репо apt-команда; у нас pacman — те же имена пакетов есть).

### П.2 Deepgram Nova-3: приватность, цена, обязательный локальный fallback

- Русский: Nova-3 поддерживает `ru` и monolingual, и multilingual (доки Deepgram,
  проверено 2026-10-26). Transcriptor шлёт потоковое аудио в nova-3 live
  (включая dual-stream ru для мультиязычных записей — опция в настройках).
- Цена (проверено 2026-10-26): Pay-As-You-Go без карты; $200 бесплатных кредитов
  (~43 000 мин ≈ 700+ ч); далее Nova-3 Monolingual streaming $0,0048/мин
  ($0,29/ч), pre-recorded $0,0043/мин; посекундный биллинг без округления.
  Для личной диктовки (1–2 ч/день) — это < $20/мес даже без бесплатных кредитов.
- Приватность: голос уходит в облако Deepgram. Подтверждено на pricing-странице:
  SOC 2 Type 1&2, HIPAA, GDPR, CCPA, PCI; есть EU-эндпоинт api.eu.deepgram.com
  (данные не покидают ЕС) — Transcriptor позволяет переопределить хост
  (TRANSCRIPTOR_DEEPGRAM_HOST). Страница /legal/data-policy не ответила (404,
  2026-10-26) — политику хранения/обучения аудио проверить на trust-странице
  Deepgram до включения в пилоте; EU-эндпоинт — дефолтная рекомендация.
- Fallback ОБЯЗАТЕЛЕН и уже встроен: движок переключается на Local Whisper
  (faster-whisper, полностью офлайн) одной настройкой; модель качается из HF
  локально; при недоступности сети warmup-эндпоинт отвечает ok:false/state:offline,
  приложение не падает. Никакой пересборки для fallback не нужно.
- Ключ: только через Ворота владельца (owner-gate ask_secret); хранить вне репо —
  export в user-юните через EnvironmentFile с правами 600 (см. П.4).

### П.3 Хоткей и автовставка в Qtile/X11 (поле opencode TUI)

- Конфликтов НЕТ: прочитан ~/.config/qtile/keys.py (146 строк, 2026-10-26).
  Ctrl+Alt+Shift+R свободен: у владельца заняты только mod+shift+r (reload
  Qtile) и mod+control+r (restart Qtile) — другие аккорды. Ctrl+Alt+Shift+V
  тоже свободен (translate на mod+shift+z). Конфликтов с XF86-клавишами нет.
- Бонус приватности: у владельца уже есть XF86AudioMicMute → pactl mute.
- Механика вставки: на X11 Transcriptor пишет текст в буфер обмена и шлёт
  `xdotool key --clearmodifiers ctrl+v` (НЕ посимвольный ввод). Для opencode
  TUI это попадание в яблочко: официальные доки keybinds (обновлены 2026-10-24)
  задают `input_paste: { key: "ctrl+v" }` — TUI вставляет из буфера по ctrl+v.
  alacritty по умолчанию перехватывает ctrl+shift+v, а ctrl+v пропускает в TUI.
- Вывод: буфер + ctrl+v надёжнее посимвольной эмуляции для TUI (одна операция,
  bracketed-paste, нет гонок с автодополнением); посимвольный вариант не нужен.
- Риск-пункт: капсула записи — отдельное Electron-окно (focusable:false,
  showInactive). В Qtile его может засосать в тайлинг — добавить float-правило
  по WM_CLASS Transcriptor (desktop/linux-wm-class.js умеет парсить WM_CLASS)
  в ~/.config/qtile (делает ИЦ на внедрении, с апрувом владельца).
- В Xephyr xdotool-путь проверяется отдельно (фокус внутри вложенного X —
  тест-кейс пилота).

### П.4 Запуск: systemd user-юнит (паттерн tg-guard) + порог ресурсов

- Паттерн снят с работающего юнита ~/.config/systemd/user/tg-guard.service:
  Type=simple, Restart=always, RestartSec=5, WantedBy=default.target,
  логи в journald. Для GUI-приложения добавляется привязка к сессии:
  After/PartOf=graphical-session.target, WantedBy=graphical-session.target,
  Environment=DISPLAY=:0 (X11 владельца).
- Ключ через EnvironmentFile=%h/.config/transcriptor/env (права 600, вне репо,
  создаёт владелец после Ворота); app-данные — TRANSCRIPTOR_DATA_DIR.
- Автозапуск при входе = тот же юнит (enable). Альтернатива — строка в
  ~/.config/qtile/autostart-x11 (менее управляемая; не рекомендуем).
- Порог ресурсов (машина: 15–16 ГБ, available 8,2 Ги на 2026-10-26):
  режим Deepgram — лёгкий (Electron ~0,3–0,6 ГБ + Python-бэкенд ~0,2 ГБ):
  MemoryMax=1G достаточно; режим Local Whisper: faster-whisper small int8
  ~0,6–1,2 ГБ, medium ~2–2,5 ГБ (бенчмарк faster-whisper: small fp32 2,26 ГБ
  во время батч-транскрипции) → MemoryMax=3G при medium. Стартуем с Deepgram +
  small как fallback → суммарно ≤1,5 ГБ, комфортно при 8+ Ги свободно.

### П.5 Локальный Whisper-резерв через Лабу (tools/lab-l9, GGUF)

- Факт: «Local Whisper» в Transcriptor — это faster-whisper (CTranslate2),
  модель качается в локальный кэш HF; офлайн-режим работает БЕЗ пересборки
  Electron — это штатная настройка движка.
- whisper.cpp (GGML/GGUF) НЕ подключается к Transcriptor как движок без форка:
  движок зашит в бэкенд. GGUF-связка с Лабой возможна только как ВНЕШНИЙ
  запасной скрипт (whisper-cli файл→текст + xdotool-вставка) — вне приложения.
- Лаба lab-l9 (~993 дока RAG-корпуса, e5-small GGUF, llama.cpp-биндинги) даёт
  готовую измерительную инфраструктуру для пилота (python-venv, замеры),
  но сама не является ASR-движком — честная формулировка для реестра.
- Рекомендация: не строить второй параллельный тулчейн. Штатный Local Whisper
  (small/medium) закрывает офлайн-резерв; whisper.cpp-скрипт — вариант-2,
  только если пилот покажет недостаточную точность/скорость локального.

- Безопасность ключей: ключ Deepgram — только через Ворота владельца;

  CLI-токен Transcriptor отдельный и узкий (только транскрипция), включать

## 4. Рекомендованный стек

**Оболочка:** Transcriptor 1.6.5 (сборка из исходников, MIT).
**Основной движок:** Deepgram Nova-3, язык ru, host = api.eu.deepgram.com
(данные в ЕС), ключ — через Ворота владельца.
**Офлайн-резерв (обязательный):** Local Whisper = faster-whisper small int8
(при недостатке точности → medium), переключение одной настройкой, без пересборки.
**Отклонённые в этой итерации:** GigaAM-v3 (torch ~2–3 ГБ + тяжёлый RAM на 16 ГБ
— проверка точности возможна позже отдельным пилотом Лабы); whisper.cpp/vosk
как внешние обвязки (дублируют готовую функциональность оболочки).

### Риски (кратко)

| Риск | Вероятность | Митигация |
| --- | --- | --- |
| Системный node/python новее требуемых → падение сборки | средняя | точные версии через fnm + uv; smoke `npm ci && npm run build` до применения |
| Политика данных Deepgram по хранению аудио не верифицирована | низкая | EU-эндпоинт по умолчанию; проверить trust-страницу до пилота; fallback на Local Whisper всегда под рукой |
| Ключ утекает в репо/логи | низкая | только Ворота; env-файл 600 вне репо; CLI-токен по потребности |
| Капсула записи втиливается в тайлинг Qtile | средняя | float-правило по WM_CLASS (ИЦ, с апрувом владельца) |
| xdotool-фокус в Xephyr отличается от боевого X | средняя | пилот прогоняет вставку в обоих окружениях; критерий в PASS |
| Потеря/дубль слов на длинных фразах (класс багов апстрима) | средняя | тест-кейс пилота: длинная фраза → сравнение начала/конца |

### План внедрения по шагам

1. Владелец (pacman, ~2 мин): base-devel git ffmpeg xdotool wmctrl zenity fnm uv.
2. ИЦ/Лаба (сборка, ~15 мин): клон репо, fnm use 22.12.0, uv venv python 3.12.13,
   npm ci в frontend и desktop, dev-запуск, smoke: запись 5 с → текст в окне.
3. Владелец (Ворота): выдать ключ Deepgram; ИЦ кладёт в
   ~/.config/transcriptor/env (600), вне репо.
4. ИЦ (конфиг): движок Deepgram, язык ru, host api.eu.deepgram.com;
   fallback Local Whisper small int8; проверка хоткея Ctrl+Alt+Shift+R.
5. Лаба (пилот в Xephyr): см. раздел 5; по PASS → приёмка владельцем.
6. ИЦ (боевой запуск): systemd user-юнит по паттерну tg-guard
   (graphical-session.target, MemoryMax=1G для Deepgram-режима);
   float-правило капсулы в Qtile; enable юнита.

## 5. План пилота для Лабы (Xephyr)

Подготовка: Xephyr :1 (владелец ставит pacman'ом: xorg-server-xephyr);
внутри Xephyr — Qtile-инстанс тест-конфига; окно-мишень №1 — gedit (базовая
вставка), окно-мишень №2 — alacritty с opencode TUI (боевой случай).
Микрофон — реальный; движки: Deepgram ru (ключ владельца) и Local Whisper small.

Метрики и протокол (каждая фраза — отдельный take, текст эталона записан заранее):

- Точность: 20 русских фраз — 10 чистых (тишина), 5 с фоновым шумом
  (музыка/вентилятор через динамики), 5 спешных/тихих; длинная фраза ≥ 100 слов
  для теста стыков. WER считает Лаба (jiwer) по аудио→текст из истории приложения.
- Латентность: стоп записи → вставленный текст (по логам приложения + секундомер
  take'ов); отдельно стриминговый интерлинг (первые слова во время речи).
- Вставка в TUI: 10/10 вставок в поле opencode TUI без потери первых/последних
  символов, без дублей, без автоотправки (пробел/Enter НЕ триггерят отправку —
  референт «отказ от автозамены по пробелу»).
- Помехоустойчивость/ресурс: RAM приложения в idle и при записи (free -h +
  systemd-cgtop по юниту), деградация WER в шуме относительно чистых фраз.
- Негатив: нет сети → Local Whisper работает; нет ключа → движок не падает,
  внятная ошибка; микрофон замьючен → красная пилюля, без вставки мусора.

Критерии:

| Критерий | PASS | FAIL |
| --- | --- | --- |
| WER чистые фразы, Deepgram | ≤ 8% | > 12% |
| WER чистые фразы, Local small | ≤ 15% | > 25% |
| Латентность стоп→вставка, Deepgram | ≤ 3 с (p90) | > 6 с |
| Латентность стоп→вставка, Local small | ≤ 8 с (p90) | > 15 с |
| Вставка в opencode TUI | 10/10 без потерь/дублей | любая потеря/дубль/автоотправка |
| RAM idle+запись (Deepgram-режим) | ≤ 1,5 ГБ | > 3 ГБ |
| Шумовая деградация WER (Deepgram) | ≤ +8 п.п. к чистым | > +15 п.п. |

Итог пилота: отчёт Лабы в 06-Audits (тот же формат провены), решение ИЦ о
боевом юните; при FAIL — повтор с medium-моделью или GigaAM-ветка отдельно.
