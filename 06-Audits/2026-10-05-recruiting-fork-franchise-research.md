# EspoCRM → свой Recruiting Pack → франшиза

> **Итог:** платный контур EspoCRM (Advanced Pack и др.) покупать не нужно —
> писать своё. Путь: relay-handler → свой Recruiting Pack (AGPL-расширение по
> прецеденту Real Estate) → агенты через официальный MCP → франшиза (агентский
> пак + управляемые инстансы) → форк ядра только по факту упора.
> Статус — **исследование**, развивать позже; коммерческая модель не оформлена.

  фиксации (честный пропуск, не выдумка).

## Платный контур EspoCRM

- **Advanced Pack** = Reports + BPM + Workflows. Цена на странице **НЕ опубликована**
  (только корзина) — `[не подтверждено]`.
- Прочие платные расширения: Sales, Project Management, VoIP,
  Outlook/Google/Zoom/Stripe/MailChimp-интеграции, Meeting Scheduler,
  Intelligence (AI).
- Бесплатные: **MCP Server**, **Real Estate**.

## Extension License

Касается только официальных платных расширений, **не ядра**:

- лицензия на **один инстанс**;
- запрет **перепродажи** и **хостинга третьим лицам**;
- запрет использования кода для **обучения ML**;
- **phone-home** (IP, домен, ключ, версия).

> **Вывод:** ещё один довод не покупать Advanced Pack, а писать своё.

## Прецедент 1 — MCP Server (бесплатно, AGPLv3, официальный)

- EspoCRM как MCP-сервер для AI-агентов через REST API.
- CRUD + Stream из коробки; настройка exposed tools из UI; кастомные tools
  дописываются; несколько endpoint'ов.
- Поддержка протокола MCP версии **2026-07-28**.

> **Вывод:** мост «агентская сеть ↔ CRM» уже существует.

## Прецедент 2 — Real Estate (бесплатно)

- Вертикальное расширение (объекты + заявки).

> **Вывод:** «Recruiting Pack» (Candidate/Object, воронки, TG-интеграция) —
> каноничная для вендора форма вертикали.

## Вердикты по компонентам

| Компонент | Вердикт | Обоснование |
|---|---|---|
| relay-handler Telegram | **да** | дни; уже ADR-002 |
| аналог Workflows/BPM целиком | **нет и не надо** | месяцы команды; нужен узкий набор триггеров |
| Recruiting Pack как расширение | **да** | Entity Manager + кастомные модули + relay; прецедент Real Estate |
| форк ядра | **можем, но пока не нужно** | бремя мержа апстрима при частых релизах; только при упоре в стену ядра |

## Лицензионные уточнения

> ⚠️ **НЕ правовой совет.** Для бизнеса нужен юрист.

1. **Форк ядра** остаётся **AGPL-3.0**; GPL-3.0 на Espo-производный код навесить
   нельзя (совместимость односторонняя GPL→AGPL). **Ребрендинг обязателен** —
   «EspoCRM» зарегистрированный товарный знак EspoCRM, Inc. (Делавэр), запрещён
   даже в домене без письменного согласия.
2. **Свои отдельные программы** (relay-handler, парсеры, скиллы — отдельные
   процессы через REST API) — **любая лицензия**, в т.ч. GPL-3.0. PHP-модули
   внутри Espo-процесса консервативно считать **AGPL-покрытыми** (продавать можно,
   исходники отдавать обязаны).
3. **Франшиза-хостинг** = network use → **§13 AGPL** (исходник всем пользователям) —
   при открытой модели не проблема, а аргумент.

## Коммерческая модель «как у EspoCRM»

- **open core** + хостинг / внедрение / поддержка / расширения.
- **Окно:** вертикаль рекрутинга линейного персонала в РФ с TG-инфраструктурой и
  агентным обслуживанием — там, где у вендора пусто.
- Вширь с EspoCRM **не конкурировать**.

## Франшиза — два слоя

### (а) Франшиза агентского пака

- top-manager + sourcing / poster / recruiter + tg-ops / intel.
- Тиражирование на объект/заказчика почти бесплатно; **второй объект = первая франшиза**.

### (б) Управляемый софт

- Инстанс Espo + Recruiting Pack на нашем VPS-поле + агенты-операторы через MCP.

### Риски (честно)

- Поддержка N инстансов (обновления ядра × клиенты).
- Изоляция данных (152-ФЗ — строго отдельные БД/инстансы).
- Секреты и доступы агентов.
- SLA («кто встаёт в 3 часа ночи»).
- Экономика VPS ~250 ₽/мес на клиента сходится, но операционка — **сервис-бизнес**.

## Эволюционный порядок

1. relay-handler + обкатка на КПО.
2. Recruiting Pack как AGPL-расширение.
3. Агенты через официальный ext-mcp.
4. Второй объект = первая франшиза.
5. Форк ядра — только по факту упора.
