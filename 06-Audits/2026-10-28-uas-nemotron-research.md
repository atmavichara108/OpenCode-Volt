# Nemotron (nvidia): исследование УАС

## Вердикт верхнего уровня

**Ни одна из 11 nemotron-моделей сейчас не может быть использована в контуре:
0 из 11 живы в рантайме.** Не «плохие» — **недостижимые**: провайдер
`nvidia` не объявлен ни в одном эффективном конфиге (глобальный, проектный),
отсутствует в `auth.json`, и в ротаторе стоит в BACKLOG. Владелец уже дважды
тестировал Nemotron как primary — оба раза падал (его слово, 10-28), и
модель `nemotron-3.5-lightning-30b-a3b` имеет его приговор от 10-23. Всё
сходится: исследование подтверждает опыт владельца фактом рантайма.

## 2. Живые прогоны (предписанная команда, 2026-10-28)

`opencode run --model nvidia/<id> -- "ответь одним словом: ok"`

| Результат | 11 из 11 |
|---|---|
| Ответ | `Error: Model unavailable: nvidia/<id>` — ни одного ответа |

**Контрольный опыт (доказывает: причина рантайм-слой, не модели):**
`opencode run --model mistral/mistral-code-latest -- "…ok"` — тоже
`Model unavailable`, хотя mistral есть в `auth.json` и probe даёт 53 ACTIVE
модели. То есть путь `--model` в этом CWD не резолвит ни один необъявленный
провайдер. Корневая причина: nvidia не объявлен в эффективных конфигах и нет
в auth.json; провайдеры mistral и прочие не объявлены в provider-блоке.

**Ротаторный слой:** `providers.json` держит nvidia в BACKLOG («вне активной
ротации/пилота до +$10 баланса»; probe 09-27: ACTIVE 460 моделей). То есть
зондом nvidia тоже не проверяется по расписанию — в живом health нет.

## 4. Вердикт по ролям

| Роль | Вердикт | Почему |
|---|---|---|
| primary | **ни одна nemotron** — сейчас и до отдельного слова владельца | 0/11 достижимы; 2 теста владельца упали; lightning — приговор; ведомственная primary — это стабильность, не эксперимент |
| verifier | пин под замену **словом владельца**; глобальный malformed-пин — брак сборки | verifier должен быть самым предсказуемым; нынешний глобальный пин не резолвится по двум причинам (префикс + провайдер) |
| obsidian-servant (SerO) | nemotron не кандидат; текущий amd-radeon/GLM-5.3-Flash оставить | живой, доказанный; SerO — не экспериментальная площадка |
| будущие кандидаты (когда провайдер будет объявлен и жив) | 1) nemotron-3.5-super-vl-120b-a12b (свежайший, мультимодальный) 2) nemotron-3-ultra-550b-a55b (text, reasoning) 3) nano-omni (если понадобится omni) | объявление провайдера = ИЦ (зона инфраструктуры); первый пуск — канарейка (штатный метод), затем — слово владельца на назначение |

## 5. Что предлагаю (решения, не факты)

1. Глобальный verifier: malformed-пин — проблема сборки; жду слова владельца
   на замену (в проектной копии он уже muse-glimmer — half-done ре-пин хуже
   отсутствия, контур двухслойный).
2. Объявление провайдера nvidia в конфиги — зона ИЦ (инфраструктура);
   без объявления весь nvidia-флот остаётся каталогом-призраком.
3. Nemotron в ротации: не торопиться — сначала объявление + канарейка, потом
   verdict по кандидатам из §4, и только затем — primary. Приговор lightning
   и два теста владельца — достаточное основание для «пока нет».
4. SSOT-сверка (DoD-1): провайдеры, живущие в каталоге, но не объявленные в конфиге,
   надо либо объявлять, либо честно вычёркивать из каталога.
