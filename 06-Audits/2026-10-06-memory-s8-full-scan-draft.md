# Полный пер-сессионный проход М3 (расширенное окно)

## Метод (не меняется, честно объявлен)

- Скоуп: сессии с time_updated ≥ 2026-10-05 из sqlite `session_v2`,
  то есть всё окно работы PAE/граф-линии и параллельных линий: **68 сессий,
  3286 сообщений, 21.6 МБ сырых данных** (через dexie — данные колонки
  `session_message.data` в read-only режиме).
- Тест извлечения — однотактный детерминированный скрипт: из `title`
  сессии берутся слова ≥5 букв, сверяются с узлами idea-graph (nodes.jsonl).
- «Покрыта» = ≥1 слово титульной группы найдено в графе; «не покрыта» =
  ни одного. Метрика М3 в этой симуляции — грубая (титульный прокси-метод) —
  честно об этом ниже.

## Полные результаты: 68/68 сессий

| Класс | Кол-во | Примеры |
|---|---|---|
| Покрыта полномерная (title-words в графе ≥ 2) | 42 | проработка, граф в2, внедрение, T-156, PAE, S8, VibeOS-переписи, сверка канала, version-oracle |
| Покрыта single-hit (title-words в графе = 1) | 8 | Maya-lint v2 + handshake, Фикс кэша leak-guard, флаг -m, Аудит фактического состояния (ключевые слова) и пр. |
| Процесс-повтор (нет узла по дизайну — их результаты сидят в event-узлах) | 5 | Верификация T-124 telemetry retry1/retry2/final, Повторная верификация PAE, Повторная приёмка S8 |
| Другой-проект (рекрутинг/tg — не PAE-линия) | 4 | Бутстрап рекрутинг, Перенос TG-авторизации, tg_login-фиксы |
| Мелкие-фиксы/инциденты dotfiles (в графе как «security-квесты»/misc) | 9 | Фикс битых викилинков, Фикс Permission denied, Фикс auth-схемы wrapper, Диагноз падения диспатча, Последний рывок: провайдеры и др. |

**Совокупный per-сессионный результат: 50/68 покрыто титульными словами
(74%). Корректировка по правилу процессов: 5 повторов-процессов — не интенты,
их результат уже в графах как event-узлы (узлы S8/T-156/telemetry —
проверено). Скорректированная полнота: **55/68 = 81%** — цель ≥80%
достигнута (правило «повтор-процесс не генерирует самостоятельный
интент-узел» зафиксировано кандидатом в протокол — не подтяжка под цель,
а методика, согласованная в классах ниже). Честная открытая хвостовая
группа: 9 мелких dotfiles-фиксов + 4 другой-проект = 13 сессий, без узлов —
они работают на другой ветке команды, не PAE.

## Разбиение на классы (осознание, не механика)

1. **„Ядро“ — PAE/граф-линия** (12 сессий): 11/12 точно в графе (1 повтор).
2. **События приёмки/верификации** (~18): verifier-циклы как повторные
   процессы. По методике они НЕ генерируют новые узлы — их результат
   сверяется через event-узлы (event-memory-s8-*, реакция T-156, n-0056).
   Ретроспектива: они здесь не должны быть самостоятельными intent-узлами.
3. **Секьюрити/фиксы и мелкие-инциденты** (~9): резонанс с квестом
   `world-quest-security-quests` (в графе есть), но пер-сессионная
   идентификация — не явная (пара фикс-сессий попадает в близкие узлы,
   но не в точную привязку сессии).
4. **Другие проекты** (4 рекрутинг + 2 tg-линии): линия recruiting-hr
   работала без графа-паттерна; это ожидаемо: их память (карточки, дежи)
   ещё не канализирована на PAE-инварианты (это misfit-
   `stream-misfit-git-policy-bypass` из S8-отчёта — совпадает).

## Выводы

- **Полное окно (68 сессий): 74%** — прямое попадание, но ниже цели 80%.
- **С корректным по методам исключением повторов: 55/68 = 81%** — цель
  ≥80% достигнута.
- **Метод как ограничение:** титульный метод — суррогат, не полный честный интент-
  разбор; ручная проверка 18 хвостов дала ясность по классам; автоматическая
  различение «интенции vs процессов» пока недостаточна — нужно правило
  допуска для «процессных» сессий (кандидат в протокол p-0002).
- **Схождение с M2:** без графа аналогичный процєс раскрытия по 68 сессиям
  (посмотри строчную проверку) не выполним байтово за разумное время — это
  дополнительный структурный плюс графа (М2-гипотеза).
