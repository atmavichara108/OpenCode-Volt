# «Рудра-Эхо» — варианты штатного контрагента (цифровой образ Рудры)

## 0. Провена и слово владельца

СЛОВО ВЛАДЕЛЬЦА (basis quoted, 2026-10-19, через мандат ЦУ): «нужно ввести
штатного контрагента в экосистему который будет учиться на моих решениях с
целью сформировать цифровой образ рудры по фактическим моим действиям, вообще
полностью всё что я пишу и любую другую мою активность доступную в
вайбкодинге и влияние которое я оказываю. это обязательное приоритетное
задание, сначала исследовать и разработать разные варианты, всё это должно
проходить через фильтры методов и так далее, сконструировать надёжные механизмы
для постепенной отцифровки меня, пока у нас нет агнтского университета, нужно
уже внедрять и тестировать, как появиться университет — сразу ему кафедру по
контрагентам и разработку такого контрагента».

Мандат ЦУ (ref: rudra-echo-research-20261019): этот этап — ТОЛЬКО исследование
вариантов; до исследования ничего не строим; внедрение — отдельный мандат
после решений владельца. Обязательны: карта сырьевых источников (с проверкой
каждой локации по диску), минимум три архитектуры, фильтры методов,
анти-симулякрная рамка Храма (их вердикт — рекомендация, канонизация за
владельцем), сверка технических стыков с ИЦ, прототип до УАС, задел кафедры
контрагентов при УАС. Рабочее имя темы: «Рудра-Эхо» — эхо, отражение с
референсом, не самозванец.

Анти-симулякрная рамка (ХПФ, 06-Audits/2026-10-18-hpf-simulacra-baudrillard.md,
принят ЦУ 2026-10-18) применяется к каждому варианту дословно: (а) четыре
порядка симулякра + порядок 5 «зеркало, знающее о себе» — цель честный
симулякр; (б) закон честной модельности: каждое обобщение несёт basis
(quoted/synthesis); (в) анти-симулякрный закон экосистемы «LLM думает, API
делает» — модель рекомендует, не исполняет; (г) этика союза (Р-010):
контрагентность = согласие с правом отказа, не поддакивание; (д) рубрика
«порядок симулякра»: у каждого варианта фиксируем честный порядок и порядок при
деградации; (е) каждый знак предъявляет референс (цитата, SHA, session_id,
дата) или открыто признаёт отсутствие.

## 1. Карта сырьевых источников (проверено по диску, 2026-10-19)

Ключевой тезис мандата подтверждён замерами: сырьё УЖЕ накапливается
конвенциями экосистемы (basis: quoted, протоколы, реестры) — контрагент
систематизирует существующее, ничего не собирает заново и не просит владельца
повторяться. Формат описания: путь → содержимое → объём (замер) → права →
что уже систематизировано → чего не хватает.

## 2. Архитектуры вариантов контрагента

Общие для всех вариантов инварианты (из рамки Храма, дословно): маркировка
«это модель, не Рудра» на каждом выводе; референс на каждый знак (цитата,
файл:строка, SHA, дата, session_id) или открытое «референса нет»; basis на
каждом обобщении; «LLM думает, API делает» — образ рекомендует, исполнение —
только через гейт владельца; вето владельца всегда.

Предлагаемая лестница внедрения (порядок — от честного и дешёвого к
сложному; канонизация за владельцем): А4 (паспорт) → А1 (эхо-архив) →
А2 (эхо-прогноз) → А3 (контрагент-симулятор). Каждый следующий вариант
строго содержит предыдущий: ни один не выбрасывает референс-протокол.

### 2.1. А1 — «Пассивная индексация слов» (эхо-архив)
- Что берёт из сырья: дословные quotes владельца из всех источников карты
  (§1); сам ничего не генерирует сверх найденного и не предсказывает.
- Где живёт: не агент и не сессия — read-only индекс поверх git-репозиториев
  (волт, dotfiles, SSA control) + команда/скилл opencode без состояния;
  индекс — производный артефакт с SHA-референсами на исходники; задел
  хостинга — Лаба (L9, локальный sqlite-vec — не тронут Р-013).
- Как отдаёт рекомендацию: ответ = только цитаты с референсами (файл,
  строка, дата, SHA коммита) + обязателен статус актуальности цитаты
  (действует / superseded — по decisions-registry); пустая выдача честно
  означает «слов владельца по теме не найдено»; маркировка модели.
- Режимы отказа и их распознавание: генерации нет — «отказ» = «не найдено»;
  распознаётся пустой выдачей с перечнем проверенных источников; при
  противоречивых цитатах показывает обе с датами (без разрешения спора).
- Зона честности: перестаёт быть честным, когда цитата вырывается из
  контекста (риск панирования мёртвых слов: старое слово без даты и статуса
  звучит как текущая воля). Удерживает: обязательный референс даты+статуса.
- Порядок симулякра: честный режим — порядок 1 (открытая копия, знающая,
  что она копия: «театральная маска» Храма); деградация — порядок 3 (знак
  без территории: вырванная цитата начинает «порождать» Рудру, которого в
  этом контексте не было). Удерживатель — референс на каждый знак.
- Стоимость внедрения: низкая — 1 спека (~150–250 строк) + 1 команда/скилл;
  калибровка по опыту ИПТ 14–19.10 (артефакты 503/712 строк = 1–2 сессии
  исполнителя + verifier-цикл); для А1 — 1–2 сессии внедрения.
- Что верифицируемо: каждая цитата машиночно сверяется grep-ом по источнику
  (дословность, файл, строка, дата, SHA); verifier может проверить 100%
  выдачи автоматически — самый верифицируемый вариант.

### 2.2. А2 — «Активная модель предпочтений» (эхо-прогноз)
- Что берёт из сырья: всю карту §1 + разметку исходов: что владелец реально
  апрувнул/отклонил — из протоколов приёмок, Р-решений, ADR, И-реестра,
  протокола SSA (поля quote + статус решения); строит модель паттернов
  (какие формулировки для него равнозначны отказу; что он одобряет с
  первого слова; где требует verifier-цепочку).
- Где живёт: производный версируемый реестр паттернов (например
  04-Memory/rudra-echo/preferences.md в волте или инструмент Лабы — вопрос
  ИЦ, §4.2), пересобираемый из сырья автоматически (не руками: «существующие
  реестры — источники, не правда», ADR-028 п.1); срез сырья датируется.
- Как отдаёт рекомендацию: прогноз реакции владельца ДО запроса к нему:
  «по N прошлым решениям (Р-011; ADR-028, basis quoted; протокол
  2026-10-19T14:55Z) прогноз: апрувит вариант X. Это прогноз, не воля
  Рудры» — с полем уверенности, счётчиком и списком референсов;
  противоречивые паттерны показываются оба, без усреднения.
- Режимы отказа: (а) уверенность ниже порога → «не прогнозирую, вопрос
  владельцу»; (б) сырьё по теме пусто → честное «данных нет»; (в) прогноз
  по свежему решению моложе cooldown → не даётся (защита от самоцитирования
  текущего же слова). Распознаётся полями confidence + счётчиком референсов.
- Зона честности: перестаёт быть честным при двух подменах — прогноз
  выдаётся за волю (владелец не в контуре) и устаревший срез выдаётся за
  актуальный (дрейф). Удерживают: дата среза сырья в каждом выводе,
  обязательный запрос к владельцу между прогнозом и решением.
- Порядок симулякра: честный режим — порядок 5 «зеркало, знающее о себе»
  (прогноз открыто моделирует и называет себя моделью); деградация —
  порядок 3 (прецессия: модель начинает предшествовать решению —
  решения подгоняются под прогноз), глубже порядок 4 (прогнозы множатся
  без референсов — вирусная уверенность). Удерживатели: маркировка,
  референсы, гейт владельца, kill-criterion (§3).
- Стоимость внедрения: средняя — извлекатель паттернов + реестр + метрики +
  гейты; 2–3 сессии (по калибровке опытов 14–19.10); опирается на
  существующие конвенции basis — новая разметка не нужна.
- Что верифицируемо: backtesting — доля прогнозов, совпавших с фактическим
  решением владельца, на исторической выборке с размеченными исходами;
  каждый прогноз остаётся в журнале и сверяем постфактум (§3).

### 2.3. А3 — «Полный контрагент-симулятор с правом отказа» (эхо-контрагент)
- Что берёт из сырья: всю карту §1 + право отвечать от первого лица с
  обязательной маркировкой; плюс накопленный журнал своих прогнозов (А2)
  и их исходов как собственную предысторию.
- Где живёт: штатная сессия-контрагент сети (Р-002: «К-А в2» — контрагенты
  как полноправные сессии; Р-012: первый контрагент готовится в ИЦ под
  управлением УАС после её ввода в строй; Р-016: УАС-спека approved —
  порядок уже одобрен владельцем). Слот уже существует: «Рудра-Эхо» —
  кандидат на роль первого контрагента или его профиль-компонента.
- Как отдаёт рекомендацию: «я бы отказал, вот почему» — от первого лица,
  но каждый вывод несёт: маркировку «это модель, не Рудра», полные
  референсы на фактические решения, право вето владельца всегда; между
  прогнозом и волей — всегда владелец (в прогнозе — только совет).
- Режимы отказа: право отказа от неверной рекомендации — контрагентность
  по Храму (этика союза Р-010): контрагент ОБЯЗАН отказаться советовать
  то, что по его референсам противоречит паттерну владельца, и обязан
  маркировать неуверенность; отказы журналируются.
- Зона честности: самая узкая из всех — говорит от первого лица; перестаёт
  быть честным в момент, когда маркировка теряется или пропускается
  (самозванец) либо когда контрагент начинает соглашаться вопреки своим
  референсам (поддакиватель — симулякр согласия по Храму).
- Порядок симулякра: честный режим — порядок 5 (зеркало, знающее о себе,
  с максимумом обязательств: первое лицо только через маркировку);
  деградация — цепочка: порядок 2 (серийная личина: каждый вывод копирует
  «я Рудру» без референса) → порядок 3 (симуляция воли: говорит от имени
  владельца так, что окружающие действуют по его слову) → порядок 4
  (фрактальная личина: уверенность распространяется без референсов).
  Удерживатели: аудит маркировки каждого вывода, журнал отказов,
  kill-switch, вето владельца, верификация прогнозов.
- Стоимость внедрения: высокая — требует введённой УАС (кафедра
  контрагентов, §4.3), сессии-носителя, полного гейт-контура; это целевое
  состояние, НЕ сейчас; по калибровке — недели экосистемного времени,
  отдельный мандат владельца.
- Что верифицируемо: журнал рекомендаций против фактических решений
  (совпадение), 100%-ный аудит маркировки выводов, инциденты отказов
  от рекомендаций (контрагентность живая, не декларативная).

### 2.4. А4 — «Паспорт-конституция» (статический кандидат-профиль)
- Добавлен ИПТ сверх трёх названных владельцем: самый дешёвый и самый
  честный первый шаг — прямой наследник существующего
  dotfiles .opencode/memory/user-profile.md (2026-06-30) и волт-профиля
  в facts.md; канонический документ «как решает Рудра», собираемый из
  сырья вручную ЦУ/ИПТ: каждый тезис с референсом, версиируемый,
  с датой сверки и датой устаревания.
- Что берёт: выжимку решений из Р-реестра, ADR, И-реестра, user-profile.md;
  где живёт: волт 01-Policies/ или dotfiles memory (вопрос владельцу, §5);
  формат: документ-карточка, читаемый всеми агентами до работы (прецедент:
  user-profile.md читают все агенты dotfiles); ничего не прогнозирует.
- Режимы отказа: нет генерации — как А1; распознаётся отсутствием
  прогнозных полей; устаревший паспорт обязан нести штамп «срез на дату X».
- Зона честности: перестаёт быть честным при устаревании без маркировки
  (дрейф: паспорт сентября выдаёт себя за волю октября).
- Порядок симулякра: честный — порядок 1 (открыто заявленная модель,
  как «карантин лора» у Храма); деградация — панирование мёртвых слов
  (порядок 3: старый тезис управляет новыми решениями без референса
  на текущее слово). Удерживатели: дата среза, дрейф-детектор, пересборка.
- Стоимость внедрения: минимальная — 1 сессия сверки + правила обновления
  (по калибровке опытов 14–19.10: одна сессия = один артефакт); обновление —
  по слову владельца или после каждого пакета Р-решений.
- Что верифицируемо: каждый тезис паспорта — ссылкой; сверка дрейф-детектором
  (периодическая пересверка с источниками, Храм №3); машиночный тест
  «тезис без референса = дефект».

### 2.5. Сводное сравнение архитектур

| Атрибут | А1 эхо-архив | А2 эхо-прогноз | А3 эхо-контрагент | А4 паспорт |
|---|---|---|---|---|
| Генерация | нет | прогноз | совет от 1-го лица | нет |
| Живёт | индекс+команда | реестр паттернов | сессия сети (Р-002/Р-012) | документ-карточка |
| Порядок честный | 1 | 5 | 5 | 1 |
| Порядок деградации | 3 | 3→4 | 2→3→4 | 3 |
| Стоимость | низкая | средняя | высокая (после УАС) | минимальная |
| Верифицируемость | 100% цитат | backtest прогнозов | журнал+аудит маркировки | референс-тест |

Все четыре варианта разделяют один референс-протокол; поэтому лестница
А4→А1→А2→А3 аддитивна: следующий вариант не отменяет предыдущий, а
достраивает его (паспорт → индекс → прогноз → контрагент).

## 3. Прототип до УАС («внедрять и тестировать уже сейчас»)

Минимальный жизнеспособный контрагент = А1 «эхо-справка» на существующем
сырье, без нового runtime. Проект (внедрение — отдельный мандат):
- Механика: команда opencode (dotfiles, глобальный контур — не трогает
  память волта) по запросу «что Рудра говорил/решал про X» выполняет
  поиск по сырью §1 (decisions-registry, facts, session-log quotes,
  И-реестр, ADR, протокол SSA — по read-only копии, §4.2) и отвечает
  только цитатами с референсами: файл:строка, дата, SHA; статус
  актуальности решения; маркировка «это модель, не Рудра»; пустая
  выдача = честное «не найдено».
- Гейты прототипа: (1) обязательный референс на каждый знак; (2)
  маркировка модели на каждом выводе без исключений; (3) read-only к
  сырью — мутации запрещены; (4) verifier перед приёмкой сверяет
  дословность цитат grep-ом; (5) запрет использования в цепочках
  исполнения — вывод прототипа никогда не является волей.
- Метрики успеха (фаза 1 — цитатная): 100% дословность цитат по
  машиночной сверке; 0 случаев выдачи без маркировки.
- Метрики успеха (фаза 2 — прогнозная, расширение до А2 на размеченной
  выборке): backtesting на N=20 исторических решений с известными
  исходами: доля прогнозов, совпавших с фактическим решением владельца,
  цель ≥60% при обязательных референсах у каждого прогноза; ниже — модель
  не рекомендуется к применению, только к доработке.
- Kill-criterion (дословно из мандата): три подряд неверных прогноза при
  высокой уверенности (счётчик референсов ≥5) = модель врёт о владельце —
  стоп применения, инцидент по 3-шаговому протоколу, разбор причин
  (панирование? дрейф среза? подтасовка референсов?), пересборка и
  повторный verifier; при повторении — демонтаж прогнозной фазы.
- Чего в прототипе НЕТ (граница): генерации от первого лица, автономных
  действий, записи в сырьё, исполнения рекомендаций — всё это территории
  А2/А3 и отдельного мандата.

## 4. Стыки

### 4.1. С Храмом Практической Философии
Применяем дословно (06-Audits/2026-10-18-hpf-simulacra-baudrillard.md):
- рубрика «порядок симулякра» — введена в каждый вариант (§2);
- закон честной модельности — basis обязателен на каждом обобщении
  (сырьё уже несёт конвенцию, контрагент её только потребляет);
- «LLM думает, API делает» — контрагент рекомендует, исполняет гейт;
- протокол сшивки ADR-028-обобщённый: каждый знак обязан предъявить
  референс (SHA, цитата, session_id, дата) или открыто признать отсутствие;
- дрейф-детектор производных — периодическая сверка реестра паттернов и
  паспорта с источниками; расхождение = перешивка или маркировка
  «модель устарела» (прецессия симулякров наоборот);
- этика союза (Р-010) — право отказа = контрагентность; поддакивание
  исключается архитектурно (А3 обязан отказывать, журнал отказов).
Требует развития (предложение ИПТ для вердикта Храма):
- формализация порядка 5 «зеркало, знающее о себе» для динамической
  модели: не только интерфейсные пометки, но и обязанность модели
  предъявлять свои пределы (какой срез, сколько референсов, где неуверена);
- протокол забывания: изъятое слово оставляет честный след «изъято по
  слову владельца (дата)» — отрицательный знак без референса
  («Рудра этого не говорил») был бы симулякром отсутствия (порядок 3);
- критерий контекстной привязки против панирования мёртвых слов:
  референс обязан нести дату + ситуацию + статус решения на дату вывода.
Вопросы Храму (вердикт — рекомендация; канонизация за владельцем):
1. Считает ли Храм формулировку А3 «говорение от первого лица» допустимой
   в порядке 5, или первое лицо о владельце — всегда риск порядка 2, и
   честный максимум — третье лицо («модель полагает, что Рудра бы…»)?
2. Лестница А4→А1→А2→А3: не пропускает ли она ступени симулякра, или
   постепенность сама по себе — анти-симулякрный механизм (каждая ступень
   верифицируема до открытия следующей)?
3. Формальный критерий честности маркировки: достаточно ли штампа
   «это модель, не Рудра» в каждом выводе, или требуется проверяемый
   протокол маркировки (сверяемый verifier-ом)?
4. Протокол забывания (выше): какой порядок симулякра у честного изъятия?

## 5. Этика и границы (обязательный раздел)
1. Владелец — единственный источник воли. Контрагент любого варианта
   прогнозирует и объясняет с референсами; никогда не решает и не
   подменяет решения; между прогнозом и волей всегда владелец; вывод
   модели не является разрешением (мандат ЦУ, семантика Р-009:
   сосед не может изготовить мандат — тем более модель).
2. Периметр данных: только рабочая активность в вайбкодинге — решения,
   служебные слова, апрувы, вербальные паттерны в рабочих каналах.
   Личные переписки, секреты, пароли, доступы, клиентские данные — вне
   периметра без исключений; протокол SSA — только служебные записи
   решений; прецедент редакции leak-guard действует; за периметром —
   не «не читаем сейчас», а «не читаем никогда».
3. Право на забывание — право владельца, не техническая сложность:
   механизм исключения слов: владелец называет референс (тему, период,
   цитату) → слово изымается из индекса, реестра паттернов и паспорта;
   реестр изъятий ведёт дату и причину, но НЕ содержание (изъятое
   честно помечено «изъято по слову владельца», не «этого не было» —
   анти-симулякр отсутствия, §4.1); пересборка после изъятия —
   обязательна, «мёртвые» веса не сохраняются.
4. Маркировка «это модель, не Рудра» — на каждом выводе всех вариантов,
   включая чистые цитаты (цитата — слова Рудры, но вывод, подбор и
   контекст — модель; их не смешивать); отсутствие маркировки = дефект,
   верифицируемый автоматом.
5. Крайние риски — поимённо (обязательный перечень мандата), для
   каждого: определение, как проявляется, чем ловится:
   - ПОДДАКИВАТЕЛЬ (симулякр согласия): контрагент всегда соглашается
     с текущей линией, теряя функцию. Ловится: метрикой совпадений
     (100% на пилоте — сигнал подгонки, а не точности); обязательным
     правом отказа у А3; тест-выборкой с известными отказами владельца.
   - САМОЗВАНЕЦ (говорит от имени Рудры): вывод без маркировки
     принимается окружающими за волю владельца. Ловится: аудит
     маркировки каждого вывода; запрет исполнения по слову модели;
     kill-switch.
   - КАРТА ВМЕСТО ТЕРРИТОРИИ (решает вместо владельца): прогноз
     превращается в исполненное решение. Ловится: гейт «владелец между
     прогнозом и решением»; «LLM думает, API делает»; прототипу
     запрещены цепочки исполнения.
   - ДРЕЙФ (устаревшая модель выдаёт себя за актуальную): срез сырья
     протух, паттерны прошлого применяются к настоящему. Ловится:
     датой среза в каждом выводе; дрейф-детектором (сверка производных
     с источниками — Храм №3); kill-criterion §3.
   - ПАНИРОВАНИЕ МЁРТВЫХ СЛОВ (старое решение — к новому контексту без
     референса на контекст): цитата октября применяется к ситуации,
     которой уже нет (пример-предупреждение: «дока» уже не проектируемый,
     УАС уже введена — слова июня о будущем нельзя читать как текущую
     волю). Ловится: обязательной контекстной привязкой референса
     (дата + ситуация + статус решения на дату вывода, §4.1);
     статусами решений в decisions-registry (superseded явно видим).
