# Часть 2 досье «Рубка управления» — платформы и подходы

Исполнитель: Институт Передовых Технологий. Мандат ЦУ (ref: control-deck-research,
переотправка по ship-mail 2026-10-25), слово владельца 2026-10-24 (basis: quoted):
«нам нужно сделать рубку управления... я хочу корабль со всеми его значимыми
интерфейсами, а под капотом будут так же крутиться сессии... нужен ли нам обсидиан
как такая прослойка или сразу заняться пип-боем; или может другие альтернативы и
подходы». Приоритет 0. Режим read-only: ни кода, ни конфигов, ни структуры —
только это исследование.

## 0. Место в досье — рамка не оспаривается

Эта работа — Часть 2 досье [[06-Audits/2026-10-24-control-deck-rubka-dossier|«Рубка управления»]].
Рамка уже собрана соседними ведомствами:

- Часть 1 (ИЦ): под капотом реально доступен открытый программный интерфейс
  opencode (сессии, статусы, сообщения, события в реальном времени, реакции,
  конфигурация) плюс чтение с диска (инциденты, реестры, журналы, база сессий
  read-only). Безопасный паттерн — «рубка-контроллер»: единственный писатель,
  опасные действия только через Ворота владельца; в вебе Ворота требуют прослойки.
- Часть 3 (Служитель): диагноз «королевства кривых зеркал 90-х» — строили
  витрину вместо пульта; концепты A/B/C, рекомендация: A сейчас (Пип-Бой-консоль +
  Обсидиан-архив), B и C волнами; Обсидиан — канон и архив.

Часть 2 отвечает на вопрос «на чём стоять экрану рубки и сколько стоит каждый
путь». Вывод совпадает с рекомендацией Служителя и не спорит с ИЦ: платформа уже
стоит на борту — Пип-Бой v11; остальные платформы оценены как источники идей
или отдельные эксперименты Лаборатории.

## 1. Критерии рубки

Рубка — операционный пульт, а не витрина (диагноз Служителя: строили витрину
вместо пульта). Реестр значимых панелей рубки Корабля:

| Панель | Источник правды | Что показывать | Управление |
|---|---|---|---|
| Корабль (обзор) | снапшот observer + git | живость экосистемы, уровень целостности | — |
| Ведомства | peer-registry + открытый API opencode (ч.1) | живые линии, кто дежурит, чем занят | будить письмом, открыть сессию |
| Квесты | 11-Quests/quests.md | статусы, блокеры | старт кнопкой |
| Здоровье провайдеров | model-catalog + probe.py (УАС) + инциденты | квоты, отказоустойчивость, ротатор | сменить модель (model-router уже умеет) |
| Решения | decisions-registry + decision-queue | карточки, ждущие слова владельца | апрув/отказ кнопкой через Ворота |
| Память | idea-graph + mem-index | граф фактов, поиск | переход в узел |
| Техдолг/аварии | TASKS.md + audit-log + инциденты | открытые дефекты, сигналы дрейфа | назначить, открыть ветку |
| Почта | ящики ship-mail (канон Р-028) | непрочитанные по ведомствам | ответ/подтверждение |
| Реестры | движков/стыков/ранбуков | свежесть операционного слоя | правка реестра |
| Рейсы/ветки | worktree + task-ветки git | кто в какой зоне, грязные деревья | открыть worktree |

Требования к каждой панели (мандат + А5 + контракт И-36):

1. Живость — данные тянутся сами: реестр изменился, вид изменился; ноль ручной
   перерисовки (корень провала v1–v3).
2. Глубина — от галактики до детали одним движением: корабль → ведомство →
   квест → файл.
3. Вход одной кнопкой — одна дверь: хоткей/rofi/глубокая ссылка, автоподъём
   хоста при входе.
4. Масштаб/зум — навигация без потери контекста (breadcrumb-тропа всегда видна).
5. Человеческий язык (А5) — статусы порогами и словами, не идентификаторами;
   машинное — под капотом.
6. Действие, а не только взгляд — нажатие ведёт к действию через разрешённый
   контур (whitelist-операции, письма, Ворота); «клик не есть кнопка» был корнем
   провала Обсидиана.
7. Управление средой через файлы — узлы экрана суть файлы волта (канон слова
   владельца 2026-10-22).
8. Локальность и ноль бюджета — всё на 127.0.0.1, опенсорс, без внешних сервисов.
9. Надёжность — авто-гашение простоя, минимум зависимостей, отказобезопасность.
10. Стиль — crypto-cyber-solarpunk (темы Phosphor/Amber/Ice уже реализованы).

## 2. Обсидиан как прослойка — честно

Плюсы (что реально даёт):

1. Уже дом: волт, память, реестры — родной формат Obsidian (ссылки, фронтматер,
   git); миграция не нужна, зона Служителя не ломается.
2. Bases живо развивается (веб-проверка 2026-10-25): живые виды из фронтматера
   без ввода данных; волна 2026 — Dynamic Views (март 2026, сетки и карточки),
   GoodBases (таблицы в духе Notion), WCC Base Views (13.10.2026), сторонние
   view-плагины; направление правильное, но источник данных — только заметки.
3. Canvas — ручной холст мышления: 00-WORLD.canvas, DECK.canvas как скелет
   навигации; формат открытый, генераторы дают JSON (портативно — ч.1).
4. Граф связей (встроенный) + плагины Juggl/ExcaliBrain — идея breadcrumb-тропы.
5. Локальность: файлы и есть истина — философия совпадает с Р-028 (ship-mail).
6. Читалка решений: deck v4 «одна дверь» уже принят владельцем как вход чтения.

Минусы (потолок как экрана рубки — подтверждаем Служителя, ч.3):

1. Нет состояния на экране: live-сессии, сокеты, поток событий opencode — вне
   ядра; телеметрия требует плагинов-самоделок в чужом рантайме.
2. Клик не есть кнопка: действий над реестрами нет (ни whitelist-операций, ни
   писем); каждое действие — словами через агента.
3. Кастомизация изнутри ограничена: свой вид = писать JS-плагин под чужой
   движок — фактически свой фронтенд, только несвободный в сборке и запуске.
4. Ручной труд: canvas — снимок, устаревает (доказано v1–v3 → v4); Bases тянет
   только фронтматер, внешние источники (live-реестры сессий) — мимо.
5. Проба уже оценена владельцем: «королевство кривых зеркал 90-х» (basis
   quoted); вторая витрина = повтор провала.

При каких условиях Обсидиан мог бы быть рубкой: если бы панели рисовали себя
сами из реестров и нажимались действиями. Первое Bases делает частично (для
фронтматера заметок), второе — не делает вовсе. Вердикт: Обсидиан — устав
корабля (канон, архив, чтение решений через deck v4), не рубка. Это совпадает
с рекомендацией Служителя (экран рубки — Пип-Бой, Обсидиан — канон и архив).

## 3. Пип-Бой v11 — действующий кандидат

Где живёт: tools/ecosystem-map/ Волта (найден по подсказке: pipboy.py +
app/modules/*.js). Линия rebuild: PR #1 влит в main 2026-10-16 (7848a46e); v11
актуальнее мокапа v9 TERRARIUM (ветка pipboy-v8-rethink, в main не слита).

### 3.1 Сервер и живость (уже частично есть — по уточнению мандата)

- pipboy.py (496 строк, только stdlib, ноль зависимостей): команды up/down/
  restart/status/open/serve; порт 8123 (переменная PIPBOY_PORT), привязка к
  127.0.0.1, только GET/HEAD (остальное отвечает 501), авто-гашение после 30
  минут простоя, pid-файл и лог в /tmp/mcode; rofi-лаунчер; глубокая ссылка
  #models из команды /agents.
- Поток событий: GET /event — Server-Sent Events; file-watcher раз в 2 секунды
  считает sha256 входов (registry.json + generated/snapshot.json), изменение
  рождает событие file.watcher.updated; heartbeat-пинг каждые 2 секунды;
  открытая вкладка с автоопросом (раз в 60 с) держит сервер живым. Транспорт
  живости работает.
- Действия: GET /action — белый список из 21 операции: workspace-open/status/
  status-all, link-open/resolve, capture-scan, term-open/status/close, query,
  blockers, next, dependencies, notify, proposals, apply, model-list/models/
  apply, dq, igraph; исполнение — actions.py. Обратный канал «нажатие →
  действие» физически существует.
- Данные: observer.py — детерминированный read-only снапшот реестров (карточки
  проектов, TASKS.md, route-log, registry.json, decision-queue, idea-graph,
  model-catalog, git-статус) плюс сигналы дрейфа (repo_missing, task_blocked,
  task_ref_missing и другие). Снапшот не есть SSOT — канон в реестрах. Это в
  точности паттерн ИЦ «чтение свободное, писатель один».

### 3.2 Экран (18 модулей, около 2,5 тысяч строк)

- app/modules/: Acceptance, Agent, Browser, Dependency, Ecosystem, Health,
  Kanban, Launcher, Link, Matrix, Models, NextAction, Projects, Proposal,
  Search, Skills, Terminal, Upgrade.
- 6 рабочих профилей (Overview/Build/Control/Models/Capture/All), 9 раскладок,
  Alt+Shift-контракт горячих клавиш (без конфликтов с qtile/tmux/браузером),
  командная палитра, rail-навигация, статус-точки и бейджи, отложенный монтаж
  тайлов (IntersectionObserver), skeleton/retry, состояние в localStorage.
- Темы Phosphor/Amber/Ice на rgba-переменных: стиль crypto-cyber-solarpunk уже
  реализован (57 полупрозрачных элементов).
- MODELS — таблица всех агентов со сменой модели точечной правкой model:
  (model-router.py: flock, бэкап, отмена тостом 9 секунд) — единственная живая
  ручка управления на борту. termproxy.py — терминалы проектов из экрана.

### 3.3 Чего не хватает до рубки (по критериям раздела 1)

| Критерий | Сейчас | Разрыв |
|---|---|---|
| Живость | SSE работает, но событие = изменение только двух файлов; снапшот гоняется вручную | авто-конвейер: watcher/крон → observer → SSE; события сессий из открытого API opencode (ч.1) |
| Глубина | Dependency/Ecosystem — плоские списки | тайлы DECK (уровни L0–L3) и GRAPH (idea-graph + breadcrumb-тропа) |
| Панели рубки | нет Ведомств, Решений с кнопками, Почты, Аварий, Ротатора как прибора | 6 модулей по списку Служителя (ч.3) |
| Действия | белый список есть, кнопки апрув/отказ нет | соединить decision-queue с Воротами через прослойку (паттерн ИЦ) |
| Вход одной кнопкой | rofi есть | автоподъём хоста при входе (решение владельца) |
| Человеческий язык | частично машинные статусы | полировка А5 |

### 3.4 Цена пути (грубо, шагами)

1. Авто-конвейер живости (юнит/крон + флаг): 1–2 шага.
2. Тайл ВЕДОМСТВА (peer-registry + список сессий из API opencode): 2 шага.
3. Тайл РЕШЕНИЯ (карточки, апрув/отказ через прослойку Ворот): 2–3 шага.
4. Тайл ПОЧТА (ящики ship-mail, непрочитанные, ответ): 2 шага.
5. Тайл ГРАФ (idea-graph + mem-index + breadcrumb): 2–3 шага.
6. Тайл АВАРИИ (инциденты + дрейф-сигналы observer): 1–2 шага.
7. Тайл DECK (уровни L0–L3, JSON-canvas рендер): 2–3 шага.

Итог: минимальная рубка (пункты 1–4 и 6) — примерно 8–11 шагов, несколько
вечеров (совпадает с оценкой Служителя); терминал 1.0 (все семь) — 13–17
шагов. Бюджет: ноль (stdlib и vanilla JS, всё в своём репо).

## 4. Альтернативы — сравнительная таблица

в реальном времени; «полу» — опрос/перерисовка; «нет» — статика.

|---|---|---|---|---|---|---|---|
| Обсидиан (Bases/canvas) | ноль | полу (виды из фронтматера; волна плагинов 2026 жива) | слабая (реестры руками) | средняя (граф есть) | нет | повтор «кривых зеркал» | канон и архив, не рубка (совпало с ч.3) |

Вывод: чужие платформы либо про метрики (Grafana), либо про HTTP-сервисы
(Homepage/Dashy), либо про новый контур (dv-hub-стек, Godot). Только Пип-Бой
уже стоит на борту, говорит с волтом и сессиями и имеет транспорт живости.
Остальные — доноры идей для тайлов (см. раздел 5).

## 5. Самый амбициозный вариант — «настоящая рубка» (без оглядки на бюджет)

Образ (от слова владельца 2026-10-22: «полёт корабля с галактикой внутри по
этой галактике... не метафорически, а уже в практическом смысле»):

- Полноэкранная трёхмерная сцена: галактика экосистемы; Корабль в центре;
  сектора = отсеки-ведомства из peer-registry; каждый отсек — светящийся узел
  с присутствием живых сессий; орбиты квестов по статусам; энергощёты
  провайдеров (пульс = живые квоты и ротатор УАС); лента событий корабля —
  route-log и audit-log как журнал машинного отделения.
- Полёт = зум одним движением: галактика → корабль → отсек → квест, решение
  или файл; breadcrumb-тропа всегда видна.
- Капитанский пульт: карточка решения всплывает с кнопками апрув/отказ
  (через прослойку Ворот — паттерн ИЦ); тревога при инциденте красит контур
  отсека и подаёт сигнал.
- Голосовой контур (перекличка с мандатом voice-input, который сейчас у ИЦ):
  доклады вслух, «статус корабля» одной фразой, диктовка ответов ведомствам.
- Вторая поверхность: старый ноутбук или планшет как приборная доска второго
  экрана (ноль денег) — дублирует приборы, пока основной экран в полёте.

Реализуемость — два стека:

1. Веб-стек (рекомендуемый путь к образу): хост Пип-Боя (бэкенд уже есть) +
   тайл GALAXY на Three.js/deck.gl/G6 (опенсорс, MIT/Apache, живы в 2026;
   WebGL повсеместен). Производительность больших графов — известная тема,
   лечится уровнями и отложенным монтажом (уже есть в v11). Цена поверх
   терминала 1.0: 3–5 шагов плюс художественное решение.
2. Godot-клиент (максимум игрового ощущения): четвёртый Godot официально
   поддерживает неигровые приложения; сцены, шейдеры, анимации; данные по HTTP
   от того же хоста 8123. Цена: отдельный контур (язык, сборка, обновления) —
   поддерживать заметно дороже, чем тайл в вебе.

Поле «реализуемость при нуле» (честно):

- Бесплатно и доступно сейчас: весь софт (Three.js, deck.gl, G6, Sigma —
  опенсорс; Godot — MIT; Textual — MIT; Grafana — свободная лицензия локально),
  хост 8123 уже наш; облачные кредиты NVIDIA (Q-001) для браузерного 3D не
  нужны.
- Стоит времени, не денег: художественное решение галактики (часы агентов),
  голосовой контур (ждёт вердикта по voice-input), второй экран (старое
  железо).
