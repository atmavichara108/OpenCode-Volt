# Досье «Рубка управления» Корабля

Задача Приоритета 0 (слово владельца 2026-10-24, basis: quoted): «нам нужно
сделать рубку управления... я хочу корабль со всеми его значимыми интерфейсами, а
под капотом будут так же крутиться сессии... нужен ли нам обсидиан как такая
прослойка или сразу заняться пип-боем; или может другие альтернативы и подходы».
Ничего не меняем — только сбор вариантов к возвращению владельца.

## Часть 1. Инфра-осуществимость (ИЦ, 2026-10-24, read-only)

### Что реально доступно под капотом
- **Открытый программный интерфейс** (opencode serve): список сессий, статусы,
  сообщения, реакции (abort/fork/summarize/revert), конфигурация и провайдеры,
  статусы инструментов, поток событий в реальном времени, управление окошком TUI.
- **С диска:** инциденты (11), база сообщений/сессий (только чтение),
  почтовые журналы, реестр решений, журнал токенов.
- **НЕ доступно:** здоровье моделей как лимиты (только факт подключения +
  инциденты), расход денег, единый список сессий разных серверов.

### Безопасный паттерн управления
«Рубка-контроллер» — единственный, кто вносит изменения; все опасные действия —
через Ворота (формы твоего решения). Чтение — свободное.

### Ворота владельца в рубке
В окошке TUI — как есть. В своём вебе — нужен небольшой прослой-сервис
(браузер не умеет держать канал форм напрямую).

### Варианты (выбор — за владельцем)

| # | Вариант | Цена | Срок | Риск |
|---|---|---|---|---|
| 1 **КонСЕРВАТИВНЫЙ** | Локальный веб-пульт поверх открытого интерфейса + чтение с диска; Обсидиан остаётся для контента | низкая | быстрый | низкий |
| 2 **РАДИКАЛЬНЫЙ** | Полный уход из Обсидиана, весь интерфейс свой | средняя | — | ломается зона Служителя, визуал Bases/Canvas |
| 3 **АМБИЦИОЗНЫЙ** | 3D-галактика как лицо рубки + всё из варианта 2 | высокая | — | риск «красиво, но не нужно» — только после твоего теста |

### Чего невозможно без чего
- Здоровье/лимиты моделей — без своего слоя телеметрии (основа уже есть).
- Единый список сессий — без закреплённых адресов серверов.
- Ворота в вебе — без прослойки.
- Живая автозамена текста — ядро не позволяет (требование записано).
- Пробуждение спящего ведомства — без вызова письменного протокола из интерфейса.

### Зависимость от Обсидиана (если уходим)
Ломается: визуал Deck (данные целы — фронтматер портативен, таблицы соберём
свои), рендер карт-канвасов (формат открытый, генераторы дают JSON), зона
Служителя (нужен мандат переноса). Теряем: живые виды без настройки, граф связей.
Выигрыш: одна поверхность вместо двух.

## Часть 3. Концепты интерфейса (Служитель, 2026-10-24, артефакт 10-Deck/drafts/2026-10-24-control-deck-concept.md)

### Диагноз «королевства кривых зеркал 90-х» (4 честные причины)
1. Deck — рисунок корабля, а не корабль.
2. Окна внутри окон (canvas в canvas).
3. Таблицы Bases — база данных 90-х буквально.
4. Ни одного действия, только чтение: управление — словами в чате. Корень: строили витрину вместо пульта.

### Мостик vs рубка
7 приборов (состояние корабля, ведомства как живые сессии, квесты, аварии, решения-на-апрув, ротатор, почта) + органы управления (апрув/отказ кнопкой, старт квеста, запуск/стоп модулей, быстрый ответ ведомству, командная строка, сигнал тревоги).

### Потолок Обсидиана
Нет состояния на экране, нет нажатий (клик ≠ кнопка), канвас ручной и устаревает; каждое действие — через агента. Вердикт Служителя: устав корабля, не рубка.

### Пип-Бой v11 как база
Уже есть: сервер на порту 8123 + поток событий на экран, архитектура модулей и событий, 18 модулей, раскладки, три темы. Не хватает: модули сессий, решений (с кнопками «принять/отказать» и ответом письмом), квестов (старт кнопкой), почты, инцидентов, ротатора. Грубая цена минимальной рубки: несколько вечеров; обратный канал «нажатие → действие» уже есть (письма + гейты).

### Три концепта
- A (консервативный): Пип-Бой-консоль + Обсидиан-архив, ASCII-пульт в файле. Дёшево, быстро.
- B (радикальный): полноэкранный HUD, отсеки, горячие клавиши. Порядка недели-двух.
- C (амбициозный): корабль как живой организм: отсеки, экипаж-сессии, лента событий, капитанский пульт. Месяцы, но эволюционно из A/B без переделки ядра.
Рекомендация Служителя: A сейчас, B и C волнами; Обсидиан остаётся каноном и архивом, экран рубки — Пип-Бой. Развилка A/B/C и судьба Обсидиана — за владельцем.

## Часть 5. Измеренные ограничения (Лаба, WIP-1, runset-1, 2026-10-27)

Замеры живого runtime (20 прогонов на эндпоинт, read-only против боевого serve):

**Дёшево для живых панелей:** статус сессии (медиана 7-9 мс), провайдеры (10 мс),
конфиг (~8 мс), список сессий дефолт (15-19 мс, 25 КБ).

**Красные зоны (не поллить):** тяжёлая статистика (cold 10 с, медиана 3.4 с — только
по кнопке); каталог моделей (45 мс, 700 КБ — кэш обязателен); полный список сессий
(81 мс, но 1 МБ за опрос — 60 МБ/мин при поллинге — только кэш/delta).

**Единый список сессий ДОСТИЖИМ** при текущей топологии (один serve + клиенты, общая
БД): диск = 1909 сессий, API с лимитом выдаёт ровно 1909. Поправка к досье ИЦ:
«разные серверы не собираются» — оптимистично/пессимистично по топологии.

**Здоровье:** инциденты — живой источник (свежий 0 ч); token-budget протух (12 суток);
provider-health.jsonl Ротатора не пополнялся с 10-23 (разрыв в работе отдела —
проверка у УАСа); API провайдеров лимитов не отдаёт — телеметрия только своим слоем.

**RED ZONE — поток событий (новое, в досье отсутствовало):** глобальный SSE
подключается за 8 мс, но сессионных событий не несёт (за 12 с — только
server.connected); события сессий уходят в их per-instance процессы, таблица событий
в БД пуста. **Следствие для архитектуры: «живая лента» рубки = слушать экземпляры
сессий или реконструкция из БД (сессии/сообщения — да; события — нет). Решать ДО
выбора варианта волны.** Полный артефакт: Лаба, tools/lab-rubka, runset-1.

### Рекомендация ЦУ
**Вариант A сейчас** — экран рубки = Пип-Бой v11; Обсидиан = канон и архив. До апрува этапа — протоколы P-1..P-6 (Служитель, зелёный дан 10-25). Условия А: авто-конвейер живости; кнопки решений — только через прослойку Ворот; приёмка этапа = живой рендер владельцем + verifier + merge по ship-порядку. Волна 2 (B) — после приёмки A; волна 3 (C) — после мокапа GALAXY. Пять открытых вопросов Института — в артефакте, ждут слова владельца.

### Кадр (исправлено по слову владельца 2026-10-27)
**Развилки здесь нет и не было.** A/B/C — РОАДМАП (волны), данный владельцем изначально.
Задача была не «выбрать вариант», а **совместно продумать архитектурный и интерфейсный
сдвиг** (слово владельца: «мы посоветовались как перейти к такому новому архитектурному
и интерфейсному сдвигу»). Досье = фактура для этого размышления, а не меню выбора.
Владелец готовит описательную базу (ЧЕГО он хочет); «КАК» — совместная работа.

### Порядок дальше
1. База владельца (описательная: что он хочет) → фиксация в волте.
2. Совместный архитектурный разбор (ЦУ + Служитель + ИПТ/ХПФ/ИЦ по нужде) → проект «КАК».
3. Протоколы (P-1..P-6) — под конкретный проект, не в воздух.
4. Роадмап волн: A (минимальная рубка) → B (терминал 1.0) → C (галактика).
