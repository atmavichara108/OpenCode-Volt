# NotebookLM как «второй brain» — исследование Института

Read-only исследование по мандату Института (docs/specs/institute-location.md).
Ничего не подключалось и не настраивалось; 04-Memory не тронут; запреты
facts.md (правило тишины T-166, урок INC-13) проверены до работы.

## 1. Возможности и ограничения (веб-поиск 2026-10-13)

- **Переименование:** с июля 2026 продукт называется **Gemini Notebook**
  (notebooklm.google/plans); существующие ноутбуки сохраняются. Все ссылки
  и обсуждения 2025 года о NotebookLM — про тот же продукт.
- **API:** у consumer-версии самозаверяемого публичного API-ключа НЕТ.
  Официальный программный доступ есть только в Enterprise-версии
  (Google Cloud, NotebookLM/Gemini Notebook Enterprise: создание и управление
  ноутбуками и источниками — docs.cloud.google.com/gemini/enterprise/
  notebooklm-enterprise/docs/api-notebooks).
- **Неофициальные CLI** (NotebookLM-py и т.п.) реверс-инжинирят
  недокументированные API: хрупко, вне поля ToS — годным признать нельзя.
- **Лимиты:** free ~100 ноутбуков, 50 источников/ноутбук, 500k слов/источник,
  200 МБ/источник, дневные лимиты чата/генераций; paid: до 300–600
  источников, 500 ноутбуков; с 02.09.2026 enterprise-лимиты сбрасываются
  каждые 5 часов.
- **Регион:** платное облако Google в РФ не продаётся; доступ к сервису из
  региона возможен через VPN/прокси [проверить] (по аналогии с Tor-прокси
  для Telegram — tools/telegram-capture). Это оперативное ограничение для
  любого пилота.

## 2. Приватность

- Enterprise: «загруженные файлы, чаты и выводы не просматриваются людьми
  и не используются для улучшения моделей» (Workspace admin docs); ноутбук
  приватен, шерится только внутри одного Google Cloud-проекта.
- Consumer: данные уходят в облако Google; гарантии слабее enterprise
  [проверить] по текущим ToS.
- Для Корабля: допустимы ТОЛЬКО публичные/не секретные материалы. НИКОГДА:
  секреты (.env*, ключи и пароли моста T-156), ПД (recruiting-hr), данные
  закрытые правилом тишины (T-166-класс), личная переписка.

## 3. Варианты интеграции (MVP)

- **А. Ручной workflow (минимально жизнеспособный, без API):** периодический
  экспорт кураторского набора публичных артефактов волта → загрузка как
  источников в один ноутбук → использование для нахождения и обзора.
  Низкий риск, нулевая стоимость, не требует ключей.
- **Б. Enterprise API-мост:** авто-зеркалирование; требует Google Cloud-
  проект, плату, VPN; это уже ВНЕДРЕНИЕ — после решения Rudra, зона
  Инженерного Центра (не Института, не либриана).
- **В. Неофициальные reverse-API CLI:** не рекомендовано Институтом.

## 4. Связь с SSOT

04-Memory волта остаётся единственным источником памяти (SSOT). NotebookLM —
ТОЛЬКО слой поиска/обзора зеркала публичных артефактов: не хранилище истины,
не авторитет, не дубль.
- Зеркалить (кандидаты): 01-Reference (публичные), 02-Methods, публичные
  06-Audits, 00-WORLD.
- Не зеркалить: 04-Memory (личные контексты/сессия-логи могут нести
  чувствительное) — правило SSOT/карантина; secrets/ПД/тишина — никогда.

## 5. Альтернативы (кратко, без ухода в сторону)

- Локальный RAG-индекс: mem-index/горячая память (И-10/И-11), self-host
  LlamaIndex/Open WebUI/AnythingLLM — данные не покидают узел; пересекается
  с зоной Инженерного Центра.
- Obsidian-стек — уже в каноне (L7 «Слуга Мира»: Obsidian-канвас/датавью);
  дешёвый второй слой без облака.
- Enterprise API — платный автоматизированный путь позже.

## Вердикт Института

ГОДНО: ручной пилот-workflow (вариант А) как изолированная проверка в
Ability Lab по слову Rudra: один ноутбук, только публичные артефакты волта
(в пределах лимитов 50 источников), без API и ключей. Критерий passing
(предложение): ноутбук находит и сводит ответ по зеркалированным артефактам
не хуже grep-уровня и с меньшим числом ходов; риски: регион/прокси,
лимиты, отсутствие программной автоматизации.
НЕ-ГОДНО (сейчас): enterprise API-мост (внедрение, после решения Rudra);
неофициальные reverse-API CLI.
SSOT-принцип: слой зеркала, не дубли истины.
