# Аудит: почему Корабль «расклеивается» и что с этим делать

## 1. Главная причина (не симптом)

**Связи между подсистемами держались на памяти и сообразительности нейронок, а не
на программе.** Каждая подсистема существует, но связь «задание → очередь дел»,
«молчание → сигнал», «строка → срок» выполнялась человеком-агентом в голове.
Нейронки по определению забывают и путаются — поэтому система и «расклеивается
раз в два дня». Лечение одно: **каждая связь становится программой с
проверяемым инвариантом.**

Второй слой причины: **дедлайны ставились «с запасом»** (часы и сутки вместо
10-15 минут). Просрочка перестала быть сигналом и стала фоном.

Третий: **подсистемы росли по одной, без общего контракта** — одна помнит про
журнал, другая про тишину, третья про реестр; общего инварианта не было.

## 2. Дефекты — причина и решение (по каждому)

| Дефект | Причина | Решение (программа) | Где сделано |
|---|---|---|---|
| Почта без реестра не адресует | адресация была на памяти линий | fail-closed: send в незарегистрированный sid = отказ; строка реестра создаётся при создании сессии; коп отсекает/регистрирует | отказ есть в шине; автопостановка строки — У-1/У-4 |
| Экран без ожиданий молчит | мандаты уходили без записей | письмо-задание автоматически рождает строку-ожидание (флаг --task) | **сделано этим ходом** (Р-120) |
| Ожидание без срока по природе события врёт | срок ставился по шкале, не по событию | срок задачи 10-15 минут (по умолчанию 15); event_at; триаж шестью видами | **сделано** (--task 15м); триаж — У-3 |
| Зов без журнала неучитываем | успешный зов не писал журнал | все случаи в журнале (ok/refused/limited/skipped) + блокировка записи; таймер как часы | **сделано этим ходом** |
| Сторож без подавления шумит | каждый повтор писал новую строку | повтор подавлен; раздутый журнал заархивирован; суточная строка сторожа | **сделано этим ходом** |
| Коп без различения мёртвых и выборки лжёт | список сессий ограничен выборкой, коп считал отсутствие смертью | коп различает: мёртв (preflight), нет в выборке (пагинация), не зарегистрирован; агент/дом сверяются с реестром | У-2 (мандат ИС) |

## 3. Почему сломалось снова (ответ владельцу прямо)

Не «баг», а **способ работы**: чинили симптомы по одному, не трогая связи. Каждая
починка была локальной (здесь зов, там срок, там журнал), поэтому следующий
разрыв появлялся в новом месте. Операция «Гомеостаз» меняет способ: сначала
контракт связей (спеки), потом задачи по нему, потом проверка критериев.

## 4. Что программа делает теперь сама (без памяти)

1. Письмо-задание → строка-ожидания (15 минут, пинки).
2. Спящая линия → зов таймером (интервал 10 минут по слову владельца).
3. Повтор дрейфа → не пишется.
4. Заявка вне реестра → истекает (две просроченные истекли).
5. Факт снятия письма → на диске с id.
6. Зов → несёт id первого письма.
7. Слово владельца → дословно на диске (persist).
8. Журнал команд → кормит счётчик токенов (замер экономии).

## 5. Что осталось (задачи У-1..У-10) и срок

Цель приоритета 0, срок достижения — **8 часов** (слово владельца: «хватит такие
длинние дедлайны»). Критерии 1-5 проверяются на срезах,confirm — владелец
(«не расклеивается» две ночи подряд).
