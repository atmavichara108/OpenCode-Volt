## 2. Модель объекта (ООП-строение, не метафора)

[О] Объект = инстанция класса с инкапсуляцией (границы), связями (порты), состоянием. Схема полей:

| Поле | Что | Пример |
|---|---|---|
| id | slug латиницей | `uas`, `apps-dept`, `ipt` |
| name / shadow | имя и тень | «Университет Агентских Систем» / «куратор агентского контура» |
| class | класс объекта | ведомство / отдел / агент / инструмент / репо / сессия |
| zone | файловая/юридическая зона | `docs/org/`, `03-Projects/` |
| boundary | что НЕ делает | «не правит код приложений» |
| owner | владелец (роль/сессия) | `ses_e9884e...` (УАС) |
| links | связи-порты | carrier-sessions, peer-address, report-address, spec-home |
| state | состояние | active / paused / draft / dead + дата |
| mandate-source | источник полномочия | Р-023 + спека done/ |

Основание [Ф]: схема дублирует манифест ведомства (11 обязательных + 4 опциональных поля, docs/org/manifest-registry.md) + канон локаций (ship-research-network: ports, carrier-sessions, spec-home). Анатомия = ЕДИНАЯ схема объектов разных классов, а не пятый реестр.

## 3. Примеры на реальных объектах [Ф — сверено с manifests/main]

- УАС: class=ведомство; id=uas; owner=ses_e9884e…; links={carrier: то же, report→ЦУ, ports: реестр манифестов}; state=active (Р-023). [Ф]
- Отдел Приложений: class=отдел; owner=ИЦ; links={контейнер-отсек → свой репо}; state=active (spec ec-departments). [Ф]
- ship-mail: class=инструмент; owner=ИЦ (pilot); links={файловая шина, waits-регистр}; state=active (Р-028). [Ф]

Смысл проверки: все четыре объекта описываются одной схемой — схема не распадается на частные случаи.

## 5. Экосистема: анализ и вердикт

[Ф] Что сейчас называется «экосистема» в объектах Корабля: реестр экосистемы (research-registry), idea-graph, 4-Memory-поля — это ЖУРНАЛЫ и ПЛОСКОСТИ, не орган.
[О] Класс объекта: Экосистема — НЕ орган, а совокупность органов + межорганные связи (aggregate). Она не исполняет действий: координация — ЦУ, стандарты агентского контура — УАС, стратегия — ЦСПиМ, память — волт.
Три варианта с последствиями:

| Вариант | Что даёт | Риски |
|---|---|---|
| Отдел «Экосистема» | владелец анатомии + дрейф-страж + сверка | дублет ЦУ/УАС на старте; бюрократизация потока |
| Функция существующего (куратор анатомии в УАС, оп. запись через ЦУ) | дешевле, без нового ведомства; раз уж УАС владеет манифестами | загрузка УАС смежной зоной |
| «Что-то на подобии» — лаборатория модели (временная сессия-испытатель) | быстрый прототип без канона | затухание после пилота |

ВЕРДИКТ ИПТ [О, канон — слово владельца]: природа Экосистемы = плоскость-совокупность, а не орган. Предлагаю: **не отдел сейчас**; ввести функцию — «Анатомия и дрейф-страж Корабля» — в зону УАС (стандарт + генерабельный реестр объектов), с операционной записью через ЦУ; Экосистема как отдел — возвращаться, когда поток органов потребует владельца (критерий: N новых органов в квартал, требующих сверки).

## 6. Генерабельность — критерий анатомии [О]

- Источники: manifest-registry + peer-registry + organ-structure + inventory инструментов (ecosystem-map) + decisions. Генератор проходит все и создаёт представление `docs/org/anatomy.jsonl` (производная, ssot:false, помечено «производное от первоисточников»).
- Гейты полноты: объект без обязательного поля (id/class/owner/state/boundary/mandate-source) = дефект слоя (не молчание).
- Гейт дрейфа: сверка с первоисточниками по расписанию (пилот: раз в неделю при реестре ожиданий); расхождение → пометка «модель устарела» (принцип дрейф-детектора из рамки симулякров).
- Гейт честности: производное помечено `ssot: false`; первоисточник всегда в поле ссылки.
