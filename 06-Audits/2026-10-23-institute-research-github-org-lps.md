## 2. Три механизма честно: цены и лимиты 2026-10-23

### 2.1 Делегирование рутины AI-агентам в репозитории (Copilot app: issue → PR)
Что это в 2026: у GitHub есть «Copilot app» — «Direct agents from issue to
merge»: назначаешь issue агенту, он делает ветку и draft PR; есть cloud
agent (исследование/код, с PR или без). Плюс MCP Registry (github.com/mcp) —
открытый каталог MCP-серверов (~560), через которые агенты подключаются
к инструментам.

Тарифы Copilot (github.com/features/copilot/plans, живая страница 2026-10-23):
| План | Цена | Coding agent (issue → PR) | Code review | Заметки |
|---|---|---|---|---|
| Free | $0 | НЕТ | НЕТ | агент-mode в IDE/CLI есть; 2000 inline-подсказок/мес; «limited chat and agent usage» |
| Pro | $10/мес | да | да | +$15 AI-кредитов/мес |
| Pro+ | $39/мес | да | да | +$70; делегирование сторонним агентам (Claude, OpenAI Codex; preview) |
| Max | $100/мес | да | да | +$200 AI-кредитов |

Контекст биллинга (2026): с 01.06.2026 Copilot перешёл на usage-based
«GitHub AI Credits» (1 кредит = $0.01); code review — множитель 13 и
дополнительно ест Actions-минуты; в сообществе — устойчивый шум о резком
удорожании после перехода.

Резонанс с нашим слоем:
- У нас контур «задача → локальный агент → ветка task/* → независимая
  проверка» уже есть: worktree-изоляция, human-in-the-loop контракт,
  verifier-гейты. GitHub-вариант дублирует его без наших гейтов: внешний
  агент не знает нашего AGENTS-контракта, работает в чужом облаке, PR
  приходит «готовым».
- Что реально даёт GitHub-вариант: работу не с нашей машины и внешним
  контрагентам. Ни того ни другого в наших требованиях нет.
- Приватность: код и контекст issue уходят в облако GitHub/моделей —
  конфликт с политикой «секреты только локально»: даже если секретов в репо
  нет, контекст задач уходит наружу.
- Бесплатный совместимый кусок: официальный GitHub MCP Server
  (github/github-mcp-server, открытый код, ~34k звёзд; локально через Docker
  с PAT) — канал чтения GitHub-данных в наш контур без внешних AI-агентов.
  MCP Registry как таковой бесплатен.

Вердикт: НЕ стоит. При нулевом бюджете механизм недоступен (Free без coding
agent; нужен Pro от $10/мес), при любом бюджете — дублирует наш контур без
наших гейтов. Единственное, что имеет смысл, — локальный MCP-мост чтения
(пилот П2).

### 2.2 CI/CD-страховка (GitHub Actions)
Живые лимиты (docs.github.com, 2026-10-23):
- Публичные репозитории: стандартные GitHub-раннеры бесплатны БЕЗ лимита
  минут («free for public repositories» — текущая публичная политика GitHub).
- Приватные: Free-план 2000 мин/мес, 500 MB артефактов, 10 GB кэш/репо;
  Pro 3000; Team 3000; Enterprise 50k. Множители: Windows 2x, macOS 10x.
  Перерасход — $0.006/мин (Linux 2-core).
- Технические лимиты: джоб до 6 ч, workflow-ран до 35 дней, 20 параллельных
  джобов на Free, матрица до 256 джобов. Self-hosted runner бесплатен
  (обсуждавшаяся плата за self-hosted private отложена бессрочно —
  вторичный источник).

Резонанс с нашим слоем: не конфликт, дополнение. Actions — детерминированная
страховка (сборка, тесты, линт) на чужой инфраструктуре; verifier —
независимая приёмка по DoD; pre-commit — локальный быстрый гейт. Три уровня
не конкурируют: локальный гейт (до push) → Actions на ветке task/* (после
push, до merge) → verifier (приёмка). Ограничение: наш код должен стать
публичным (ради безлимита) или вписываться в 2000 мин/мес приватных;
секреты в тексты workflow класть нельзя.

Вердикт: полезно для открытых несекретных проектов — бесплатно и безлимитно
(по текущей политике — навсегда). Для приватных — нейтрально: 2000 мин/мес
малому проекту хватает, перерасход закрыт $0 spend limit на Free-плане.

### 2.3 Облачные среды (Codespaces)
Живые лимиты (docs.github.com и github.com/features/codespaces, 2026-10-23):
- ЛИЧНЫЕ аккаунты: Free — 120 core-часов/мес (≈60 ч на 2-ядерной машине)
  + 15 GB-мес хранилища; Pro — 180 ч + 20 GB.
- ОРГАНИЗАЦИИ (включая Free-план): бесплатной квоты НЕТ вообще.
  Pay-as-you-go: $0.18/ч за 2-ядерную машину, $0.07/GB-мес; требуется
  платёжный метод.
- Приватность: код, среда и зависимости — на машинах Microsoft/GitHub.
  Наша модель — локальная машина (Manjaro), стек локальный; Codespaces
  эту модель ломает.

Бесплатные альтернативы без облака:
- devcontainer CLI — открытая реализация стандарта (devcontainers/cli;
  npm/brew). Тот же .devcontainer/devcontainer.json, что читает Codespaces,
  но контейнеры крутятся локально в Docker/Podman. $0, данные на нашей машине.
- DevPod — клиентский раннер devcontainers без сервера (открытый); Coder —
  self-hosted CDE (открытый).
- Gitpod self-hosted МЁРТВ: deprecated, репозиторий self-hosted архивирован
  2026-04-24; сам Gitpod перебрался в Ona (2025-09), Gitpod Classic закрыт
  2025-10-15, компанию купил OpenAI (объявлено 2026-06-11).

Вердикт: Codespaces — не стоит (организациям бесплатно не даёт ничего,
приватность, ломает локальную модель). Стандарт devcontainer локально —
полезно: даёт воспроизводимость среды, которую Codespaces продаёт, без
облака, без денег и без утечек.

## 3. Пилоты для Лабы (предложение, не исполнение; внедрение — после слова владельца)

### П1. Actions-страховка на тестовом публичном репозитории
- Гипотеза: публичный репозиторий получает бесплатный безлимитный CI,
  который дополняет наши локальные pre-commit-гейты независимой проверкой
  на чужих раннерах.
- Что делаем: тестовое публичное несекретное репо (toy-проект на TypeScript;
  можно форкнуть WTD или создать своё), один workflow: линт + сборка +
  тесты на push/PR. Проверяем на деле: минуты не списываются, очереди
  короткие.
- Критерий успеха: workflow зелёный на 10+ пушах подряд; $0 списаний;
  типовой прогон < 5 мин; статусы видны на ветках task/*.
- Kill-criterion: GitHub требует платёжный метод за что-либо в цепочке;
  лимит режет даже публичный репо; очередь стабильно > 15 мин.

### П2. Issue из GitHub → задача в наш контур (локальный MCP-мост чтения)
- Гипотеза: GitHub-issue можно принять как внешний триггер задачи для
  локального агента (OpenCode-сессия) без внешних AI-агентов, без затрат
  и без утечек.
- Что делаем: официальный GitHub MCP Server локально (Docker; fine-grained
  PAT только на чтение тестового репо) или минимальный скрипт gh CLI по
  расписанию. Issue → файл-задача в нашем формате → обычный контур: ветка
  task/* → работа → verifier.
- Критерий успеха: issue из тестового репо превращается в задачу с ID в
  нашем контуре; контур запускается; токен и данные не покидают машину; $0.
- Kill-criterion: для чтения issues нужен платный тариф или внешний
  AI-контур; УАС фиксирует конфликт «одного источника».
- Зависимость: запуск только после ответа УАС на У-1/У-2 (раздел 4).

### П3. devcontainer локально вместо Codespaces
- Гипотеза: открытый devcontainer CLI + Docker/Podman на Manjaro дают
  воспроизводимую изолированную среду проекта — «облачную» повторяемость
  без облака и денег.
- Что делаем: один .devcontainer/devcontainer.json для Python-проекта
  (direnv + .venv внутрь); devcontainer up; проверяем работу агентской
  сессии внутри контейнера.
- Критерий успеха: среда поднимается < 5 мин; зависимости изолированы;
  файлы не выходят за пределы машины; агент работает; $0.
- Kill-criterion: ломает direnv/агентский слой; overhead старта/диска
  неприемлем.

## 4. Вопросы УАС (агентский слой; отправит письмом сессия Института после этого коммита)

## 5. Вердикт и открытые вопросы владельцу

### Вердикт (честно)
1. Организация LPS бесполезна как объект «использования»: пустая, спит с
   2023-10-31, единственный репозиторий — учебно-пет проект без лицензии,
   бэклог мёртв. Держать её «на всякий случай» нет причин; если WTD
   понадобится как песочница для публичных пилотов — годится, но не лучше
   любой toy-альтернативы.
2. Три механизма при нашем нулевом бюджете и своём агентском слое:
   - Делегирование GitHub-агентам — не стоит: бесплатно недоступно (Free
     без coding agent, нужен Pro от $10/мес), дублирует наш контур без
     наших гейтов, выносит код и контекст задач в облако.
   - Actions — полезно с оговоркой: публичным репо — бесплатный безлимитный
     CI (по текущей политике — навсегда), приватным — 2000 мин/мес. Это НЕ
     замена verifier-гейта, а страховка уровня «собралось / тесты прошли»
     на чужих раннерах.
   - Codespaces — не стоит: организациям бесплатной квоты нет вообще,
     личная квота ломает локальную модель и уводит данные в облако.
     Бесплатная альтернатива — devcontainer локально (полезно).
3. Единственные кандидаты в работу за $0: Actions на публичном тестовом
   репо (П1), локальный MCP-мост чтения issues (П2, после УАС), devcontainer
   локально (П3).

### Открытые вопросы владельцу
1. Жив ли вообще проект WTD и планируется ли его развитие? Это честная
   переформулировка вопроса внешнего анализа «какую рутину в WTD сильнее
   всего скинуть на агентов»: по всем видимым признакам проект мёртв с 2023
   года, «рутины» в нём нет; если он для вас жив — скажите, в чём цель, и
   мы пересчитаем разбор под неё.
2. Готовы ли мы открыть какой-нибудь наш (или новый toy) проект публично
   ради бесплатного безлимитного Actions-CI? Где граница открытости?
3. Есть ли у нас реальная потребность работать «не с нашей машины»
   (в поездках, с телефона)? Если нет — облачные среды закрываем окончательно.
4. Нужен ли нашему контуру внешний триггер задач из GitHub-issues (П2),
   или наш контур задач замкнут и внешние триггеры — лишний шум?
