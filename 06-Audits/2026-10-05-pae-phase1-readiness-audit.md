### 5.3 Где диетеза разрешена, где нет

**Разрешено (внутри):** OpenCode-Vault целиком, session-log'и, идеи в графе,
VibeOS, карточки, route-logs, спеки PAE, письма peer-comms (межагентные).
**Нейтральный язык обязателен (наружу):** коммиты внешних проектов
(recruiting-hr, AndroidOS, serp, dv-hub, TradingMind); README и публичные
публикации; deploy-манифесты; любые вложения во внешние системы
(Telegram, форки, рассылки).

### 5.4 Режимы

- **Режим A — strict lint-gate:** словарь как denylist-паттернов;
  точка интеграции — шаг в pre-commit-хук / release pipeline; область проверки —
  внешние пути (коммиты проектных репо, README, публикации):
  `grep -Ei 'velzebub|allis maya|обжорство|harvest' <external paths>` → FAIL коммита.
  - Плюс: гарантия на месте.
  - Минус: требует стабильности словаря; риск ложных срабатываний на
    пересечениях обычных слов.

- **Режим B — norm-vs-audit:** словарь и правило фиксируются как нормативные
  (этим подразделом). Проверка — периодический auditor-пробег (subagent,
  вне runtime): сверяет внешние артефакты за окно (напр., 3 недели)
  с нормой и докладывает об отклонениях.
  - Плюс: дешёво, толерантно к нестабильности словаря, не тормозит работу.
  - Минус: первое нарушение возможно найти только post-hoc.

### 5.5 Рекомендация сессии

Стартовать с **Режим B (norm + аудит)**, потому что (i) словарь ещё не стабилен,
(ii) сейчас важнее не тормозить PAE-рост раньше времени, (iii) существующий
pre-commit этап волта позволяет добавить ретроспективный аудит дёшево.
Прикладной шаг: «проверка внешних коммитов AndroidOS/recruiting-hr за последнюю
неделю» — auditor-пробегом в ближайшие 7 дней → первая обратная связь для словаря.
Переход к **Режиму A (strict)** — после 2–3 фаз стабилизации словаря (по мере
Фаз 2/3 PAE).

### 5.6 Точка интеграции (для обоих режимов, по выбору Рудры)

1. Внутренняя норма: `02-Methods/maya-boundary.md` (правило + словарь)
   или спека `docs/specs/maya-lint.md`.
2. Внешний enforcement (Режим A): `git pre-commit hook` в проектах
   (`recruiting-hr`, `serp`, `AndroidOS`, `dv-hub`, `TradingMind`) через
   `tools/maya-lint/validate.sh` (реализация — не в мандате).
3. Драфт ведёт базовый список терминов (§5.2); полноценный mapping и
   привязка к файлу внешнего применения — после выбора режима Рудрой.

## 6. Живой тест графовой памяти (S8 amend — в мандате этой сессии)

### 6.1 Методика

1. **Токеноёмкость дистилляции (≥10×):** `ratio = raw_bytes(диалог в скоупе) /
   байты idea-graph-дистилляции этого скоупа`
2. **Экономия при извлечении (≥3×):** время/токены ответа на «вспомни контекст X»
   с графом vs полная перечитка сессийных логов (re-read).
3. **Полнота (≥80%):** доля интентов сессии, дошедших в граф как узлы,
   от интентов первичного потока.
4. **Живучесть (100%):**
   валидатор PASS после каждого события (fork/compact/append).

### 6.2 Бейзлайн (первое измерение, приближённое — derived, не канон)

- **Raw поток:** ≈ 4.64 МБ суммарных данных 4 главных сессий PAE/граф-линии
  (691 сообщение; sqlite `session_message.data`). Честная оговорка: сырые
  байты включают tool-part'ы, которые дистилляция переносить не обязана —
  поэтому оценка сверху, а не строгая.
- **Атомы (дистилляция):** `04-Memory/idea-graph` = **126 КБ** (nodes/edges/
  protocol/README/index, 5 файлов).
- **Ratio:** ≈ **36.8×** raw → атомы (по сырым байтам). Методическая цель
  ≥10× — формально достигнута; точная метрика требует вычитания tool-байт.
- **Полнота:** 33 intent-узла в графе; каждая суть зафиксирована или привязана
  через emitted → формально 100% по перечисленным, но выборка одна —
  производная, не канон.
- **Живучесть:** валидатор PASS (exit 0) после каждого аппенда этой сессии
  (4 из 4), включая уже прошедший fork-сценарий соседней линии.

### 6.3 Что не измерено (честно)

- **Экономия извлечения (метрика 2):** нужны контрольные ходы «без графа»
  (формулировка S8) — по S8 измерение в мандате этой сессии; зафиксировано
  как открытая точка с определённым стартом.
- **Пер-сессионная полнота (метрика 3 в полном виде):** требует прохода
  «интенты per session» по всем 15 сессиям; зафиксирована как методический
  следующий шаг (сейчас в графе 33 intent-узла).
