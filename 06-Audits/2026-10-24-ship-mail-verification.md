# Верификация ship-mail (пилот Смотрителя ДВ-Хаба)

**Решение:** Р-028 — ship-mail становится каноническим транспортом писем.

## Что проверено ЦУ (2026-10-24)
- Тесты: 7/7 PASS (доставка, идемпотентность, различные id, inbox/show/ack,
  отказ вне реестра получателю и отправителю, отказ без реестра).
- Живой дым: send (DELIVERED, атомарный файл) → inbox (unread 1) →
  show (OKF-шапка + тело) → ack (файл в read/) → status (read 1, unread 0) →
  дуубль-отказ (exit 3, второго файла нет). Адресат — сессия ЦУ, из peer-registry.

## Почему лучше старого канала (letter.sh/run-инжект)
| Класс проблемы | Старый канал | ship-mail |
|---|---|---|
| «Ложное sent» + потеря письма | журнал пишется до запуска, сбой = потеря | файлы и есть истина, write-once |
| Отказ адресату без агента | run-инжект падает | адресация по строке реестра |
| Цена доставки | ход модели в сессии получателя | ноль ходов, атомарная запись |
| Ожидание (busy-check/TTL/drain) | нужна механика | не нужна: статус = место файла |
| Читаемость владельцем | нет | cat/Obsidian, OKF-файл |

## Ограничения (осознанные, из спеки)
- Не срочное прерывание: аврал — владелец или старый канал.
- Без подписей: доверие как у peer-comms (одна машина); за пределами ноутбука — подписи.
- Реестр адресов остаётся прежним SSOT (peer-registry, INC-18).
