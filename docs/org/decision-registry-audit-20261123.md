# Сверка двух реестров решений и прослеживаемость канона — 23.11.2026

Задача хода: каждый канон моего слоя (`docs/org/`: реестр имён, реестр манифестов) должен
вести к записи слова владельца **в реестре решений**, и ни одно решение не должно висеть
без адреса. Канон «письмо ≠ память» работает только если адрес есть.

Метод: прочитаны оба реестра целиком; id собраны регуляркой и сопоставлены; для каждой
строки реестра имён и реестра манифестов проверено, есть ли id решения-источника; по
рекрутинговому контуру — история спеки через `git log`/`git show`; по слово владельца —
цитаты в `01-Policies/decisions-registry.md` (`basis: quoted`) и в
`~/Projects/recruiting-hr/docs/canon/roles.md`.

### Н-17. «Outrich-office» — это вывод УАС по образцу, а не дословное имя владельца

По диску: Р-Д-009 (30.10) задаёт образец офисной модели — «Офис Серплюкс - serp-office +
добавить агента для разработки … - senior-dev»; Р-Д-011 (30.10) — «Аутрич Цеху - Senior-dev».
Дословного имени для **офиса** линии Аутрич владелец не называл: «Outrich-office» — это
применение канона Р-Д-009 («офис = `<имя>-office`») к линии Аутрич, то есть **вывод УАС**.

**Почему это важно:** вопрос владельцу «подтверди имя Outrich-office» был поставлен неверно
— слово владельца его не давало. Правильная постановка: либо владелец называет офис Аутрича,
либо остаётся вывод УАС с пометкой. Это же снимает часть путаницы с коллизией `Senior-dev`
(Н-13): канон Аутрич·Цеха — слово владельца (Р-Д-011), а «Outrich-office» — мой вывод.
