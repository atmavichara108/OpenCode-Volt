# Имена агентов-носителей ведомств

Вердикт владельца 2026-10-30 (реестр Р-Д-009, `basis: quoted`). Все имена — с
заглавной буквы. Существующие агентные файлы/пины не трогаются этим реестром —
реестр фиксирует **каноническое имя**, файлы сессий создаются/правятся в своих
репозиториях (маршрут — ЦУ/ИЦ; манифест ведомства — при необходимости).

Разделение на «живые» и «запланированные» приведено к факту 19.11: в «живые»
перенесены ведомства, у которых есть **и** файл агента в глобальном слое
(`~/.config/opencode/agent/`), **и** живая сессия-носитель в
`04-Memory/peer-registry.md`; в «запланированные» остались единицы без
носителя. Сверка — `docs/org/agent-carrier-audit-20261118.md` (раздел
«Уточнение 19.11»).

**Что в реестр НЕ входит (факт на диске 21.11, сверка всех 37 файлов живого слоя
`~/.config/opencode/agent/`):** агенты-носители ведомств — это primary своей
сессии. Отдельных строк не имеют: субагентские роли (`reviewer`, `verifier`,
`researcher`, `tree-cop`, `system-audit`, `system-ops`, `meta` — `mode: subagent`),
режимы, отключённые словом владельца 19.10 (`build`, `plan` — «убран из
агентского контура»), и аварийная дверь `emergency` (`mode: primary`, но по
своему описанию «не рабочая роль»). Строка появляется, только если такая роль
становится носителем ведомства.

**Граница охвата (уточнено 22.11):** сверка 37 файлов — это **глобальный слой**
`~/.config/opencode/agent/`. Кроме него на диске есть **18 агентских файлов в
продуктовых слоях** (SERP — 10, seo-outreach — 4, dv-hub — 2, ability-lab — 2) и
**6 в рекрутинговом проекте** (`~/Projects/recruiting-hr/.opencode/agents/` — каталог
назван `agents/`, не `agent/`). Это субагенты продуктов и линий, не носители
ведомств, поэтому строк реестра им не полагается, — но «реестр имён проверен
целиком» читать так нельзя: проверен глобальный слой, продуктовые слои — отдельно.
Сверка 22.11 по всему контуру: `docs/org/agent-names-audit-20261122.md`.
