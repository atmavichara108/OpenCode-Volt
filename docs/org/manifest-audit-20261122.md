## Находки

### Н-1. Представитель Корабля: адрес переписки нерабочий (связь без сигнала)

- **Факт:** `docs/org/ship-representative-maya.md`, строка 22: `peer-address:
  ses_e9284e4aeffe7okjn4f7RtavmG`. В `04-Memory/peer-registry.md` такой сессии нет
  (0 совпадений). Строка записана 29.10 коммитом `11861447` (автор — владелец) и
  отличается от id сессии УАС `ses_e9884e4aeffe7okjn4f7RtavmG` ровно одним символом.
  Второй адрес в реестре сессий есть.
- **Почему не чиню молча:** строка — из коммита владельца; переписывать его слово без
  его слова нельзя.
- **Кто решает:** ЦУ — операционная запись реестра сессий и маршрут почты; УАС вносит
  результат в манифест. Слово владельца нужно только если адресатом меняется сама
  идентичность представителя (тогда — реестр решений).

### Н-2. Реверс-инженерия движков: статус active при мёртвом носителе

- **Факт:** строка реестра сессий `ses_ewdWZMlHOJE3UloUrwdXHi` помечена «мёртв»

  удаление). Манифест это уже фиксирует в `status` и `carrier-sessions`.
- **Нужно:** новый носитель (ЦУ/владелец) или смена статуса на «proposed, ждёт
  носителя». До этого ведомство живым не является, хотя формально `active`.
