отдельно; утверждения, которые являются выводом УАС по факту, помечены так.

Расхождения — не в каноне имён, а в оперативных ячейках и в неохваченных линиях.

### Н-9. Рекрутинговый контур: три живые линии без канонических имён (слово владельца)

Строки реестра сессий 42–44: **Смотритель HR**, **Офис (recruiting-линия)**, **Отдел
Разработки HR** — все живые, ячейка агента во всех трёх: «interim librarian (имя агента —
слово владельца)». В реестре имён эти ведомства **не заведены** — там их нет вообще
(проверка: 0 совпадений по «recruiting»/«HR»).

Факт по проекту `~/Projects/recruiting-hr`: агентские файлы есть, но в каталоге
**`.opencode/agents/` (множественное число, не `agent/`, как в глобальном слое)** — 6
файлов: `top-manager.md` (mode: **primary**, «Дежурный менеджер кейса — маршрутизация,
воронка, метрики, интервью»), `recruiter.md`, `sourcing.md`, `poster.md`, `build.md`,
`verifier.md` — все субагенты, кроме первого.

Канон решения есть: **Р-078** (слово владельца 04.11, `01-Policies/decisions-registry.md`)
— рекрутинговое агентство снято с паузы и введено в экосистему, названы линии и их
адреса; **имён агентов Р-078 не даёт**. Отсюда: имя линии — слово владельца; ячейки
реестра сессий правлю не я (операционная запись — ЦУ).

*Где лежит это слово:* в реестре решений слоя `docs/org/` строка Р-078 **не
продублирована** (там по рекрутингу только Р-Д-007 — «рекрутинг пока на паузе», 29.10);
канон — в `01-Policies/decisions-registry.md`. Дублировать слово владельца во втором
реестре решений я не стал: для реестра имён это внешняя ссылка на уже канонизированное,
а не новый источник правды.

### Н-10. Обоснование «interim librarian» устарело: файлы агентов уже есть

В ревизии 18.11 строки с «interim librarian» (Отдел «Движков», Реверс-инженерия, СБ,
Кафедра контрагентов) были помечены как «не дефект: носителей ещё не создано». **По диску
22.11 это обоснование больше не верно**: файлы канонических агентов созданы 19.11 и лежат
в глобальном слое — `engine-keeper.md`, `reverse-craft.md`, `sb.md` (все `mode: primary`,
описания совпадают с каноническими именами). Канон имён не изменился — устарела
**формулировка** в реестре сессий. У Реверс-инженерии к тому же строка помечена «**мертв**
(preflight 404 на 20.11)» — это Н-2, ждёт слова владельца.

### Н-11. Коллизия имени файла `top-manager` в двух ведомствах

- глобальный слой `~/.config/opencode/agent/top-manager.md` — **Top-manager**, носитель
  control-top (`ses_ed5fcec4effeZKwSoEmMe6Swlk`), канон Р-Д-009;
- проектный слой `~/Projects/recruiting-hr/.opencode/agents/top-manager.md` — «Дежурный
  менеджер кейса», mode: primary, линия рекрутингового агентства, имя не канонизировано.

Два разных агента с одним именем файла в разных слоях. Для контура это не ошибка
(слои разные, вызов по каталогу), но в отчётах и в разборе «top-manager» без уточнения
слоя означает разное. Решение по именованию рекрутинговой линии — вместе с Н-9.

### Н-12. Формулировка охвата в реестре имён уже, чем факт

В реестре имён сказано: «сверка всех **37 файлов** живого слоя `~/.config/opencode/agent/`».
За пределами этого охвата — **18 агентских файлов в продуктовых слоях** (SERP — 10,
seo-outreach — 4, dv-hub — 2, ability-lab — 2). Они не носители ведомств (субагенты
продуктов), строк реестра им не полагается — но формулировку стоит уточнить, чтобы
«реестр имён проверен целиком» не читалось как «проверены все файлы агентов».
Уточнение внесено 22.11 в текст реестра.

Форма владельцу о разведении коллизии `Senior-dev` подана 21.11 — ответа нет. Плюс
коллизия с субагентом SERP (Р-Д-009) — то же слово владельца на два разных места.
