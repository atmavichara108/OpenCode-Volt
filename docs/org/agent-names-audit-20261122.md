**Механизм переключения агента живой сессии — установлен по диску:** в OpenCode V2
(локальная версия **v2.3.2**) сервер отдаёт эндпоинт
`POST /api/session/{sessionID}/agent` с телом `{"agent": "<id>"}` — «Switch session agent»
(OpenAPI живого сервера, `/openapi.json`). `id` агента — basename его файла; в живом
каталоге `/api/agent` — 41 агент, и все нужные (`spellmaster`, `skolar`, `foreman`,
`mechanic`, `shtab`, `sb`, `engine-keeper`, `rector`, `ui-ux-dev`, `obsidian-servant`,
`top-manager`, `serp-office`, `bizmaster`) на месте. То есть переключение — одна
операция API, а не правка файлов; **кто её исполняет** — зона владельца сессии (ЦУ) либо
моя по их прямому поручению: имя `Spellmaster` — выбор Корабля, не слово владельца
(как и `Skolar`), поэтому фактическое переключение живого носителя я без слова владельца
или прямого поручения ЦУ не делаю. Прямое поручение ЦУ получено (`cu-uas-switch-spellmaster-1122`)
— результат в следующем подразделе.

*Границы проверенности этого абзаца:* версия v2.3.2, эндпоинт `/api/session/{id}/agent`
и счётчик «41 агент» — это **проба автора** (живой сервер: `opencode --version`,
`opencode api get /openapi.json`, `opencode api get /api/agent`); независимой проверки
этих чисел у проверяющих не было. Саму версию журнал OpenCode
(`~/.local/share/opencode/log/opencode.log`) подтверждает: в нём **более 570** записей
`version=2.3.2` (рядом — более старые 2.2.6 / 2.2.7 / 2.3.0; журнал живой и растёт, поэтому
точный счёт на момент чтения у разных читателей различается). На момент составления
этого блока переключение **не выполнялось**. Всё, что проверяющие подтвердили по диску,
— это 10 ячеек реестра сессий, коммит `e87c9893` и «оставшееся открытым».

### Переключение Кафедры заклинаний — выполнено 22.11 (прямое поручение ЦУ)

ЦУ решил (`cu-uas-switch-spellmaster-1122`, прочитано и подтверждено): имя `Spellmaster` —
канон (Р-118, выбор Корабля), а операция техническая и обратимая, слово владельца на неё
не требуется; ведомство попросило переключить носителя сейчас. Исполнено одной операцией:

```sh
opencode api post /api/session/ses_spe11s2026no7Chair01/agent --data '{"agent":"spellmaster"}'
```

**Факт по диску (проба автора, 23:05:46 MSK):** сессия-носитель **уже была** на агенте
`spellmaster` ДО операции — `GET /api/session/ses_spe11s2026no7Chair01` перед вызовом
показал `agent: spellmaster`, после вызова — то же. То есть переключение оказалось
**идемпотентным**: значение агента не изменилось, запись сессии обновилась (`updated` =
23:05:46.741 MSK, ровно на 8 мс после вызова, который журнал OpenCode зафиксировал в
20:05:46.733Z; в журнале — ровно одна запись этого вызова, версия 2.3.2).

**Следствие по Н-7:** по Кафедре заклинаний технического разрыва **не было** — живая
сессия уже была на каноническом агенте; формулировка ячейки реестра сессий «переключение
сессии-носителя — по слову владельца» описывала процедуру, а не расхождение. **Ячейка
освежена ЦУ 22.11** (коммит `1b709d2e`, push в `origin/task/next-20261114`) — теперь
«Spellmaster (Р-118; файл агента spellmaster.md, живая сессия на spellmaster — переключение
выполнено УАС 22.11)»; проверено по диску (строка 50 реестра сессий). Пункт закрыт.
