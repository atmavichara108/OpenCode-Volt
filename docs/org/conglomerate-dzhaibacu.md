## 2. Канбан: где он реализован и что значит «общий стандарт как в ДВ-Хабе»

**Слово владельца:** «канбан который реализован у фриланса нужно передать контрол топу и
скрам мастеру», уточнение — «канбан по общему стандарту как в дв-хабе», одна общая доска.

**Доска фриланса — по факту:**

- `~/Projects/freelance-line/docs/playbooks/kworks/kanban.md` — `type: Board`,
  `ref: kwork-kanban`, статус «active (заведён 18.11)»;
- правила ведения: `docs/canon/kwork-production.md`; один активный кворк (WIP = 1), у
  каждого своя ветка `kwork/NN-имя`, карточка — `docs/playbooks/kworks/kNN-*.md`
  (**13 карточек**: `k1`–`k3`, `k10`–`k19`; `kanban.md` — сама доска, не карточка —
  итого 14 файлов `k*.md` в каталоге);
- доска обновляется **в том же коммите, что и карточка**; генератора доски в репозитории
  нет;
- `status` в карточках — **свободный текст** («queue (черновик карточки; в работу — по
  решению владельца)», «перерабатывается по правкам владельца…») — словаря нет.

**Стандарт ДВ-Хаба — по факту** (источник `~/Projects/dv-project/scripts/rebuild-kanban.sh`):

- **источник правды — frontmatter карточек** (`DV-*.md`, поле `status`); доска —
  **производная**, пересобирается скриптом, руками не правится;
- **словарь статусов ровно 4**: `backlog | ready | in_progress | done`; невалидный статус —
  скрипт падает (код 3) и доску не трогает;
- порядок столбцов: In Progress → Ready → Backlog → Done;
- порядок карточек внутри столбца — **порядок обхода файлов `DV-*.md`** (glob,
  лексикографически); **сортировки по приоритету в коде нет**: приоритет выводится
  только эмодзи-маркером. Проверка по живой доске: столбец Ready — DV-012 (P1),
  DV-041 (P2), DV-042 (P1) — не по приоритету. *Расхождение внутри скрипта:*
  его шапка заявляет «по приоритету (P0→P3), затем по ID», кода сортировки нет —
  по Р-121 в силе код;
- карточка несёт `id`, `title`, `status`, `priority`, `effort`, `epic`, `assignee`,
  `created` (45 карточек из 46 содержат `assignee`/`created`), но **скрипт читает только
  6 полей** — `id`, `title`, `status`, `priority`, `effort`, `epic`; `assignee` и
  `created` на доску не выводятся;
- правило доски: «стартовала — сразу In Progress; выполнена — сразу Done».

**Разрыв (вывод УАС по факту):** доска фриланса этому стандарту **не соответствует** —
нет словаря статусов, нет генерации, `status` — свободный текст, правило «правь статус в
карточке, доска пересобирается» не действует. То есть «передать по общему стандарту как в
ДВ-Хабе» — это не перенос файла, а смена способа ведения.

**Две копии доски ДВ-Хаба — по факту:** рабочая — `~/Projects/dv-project/DV/Operations/Kanban/Kanban Board.md`
(коммит `2b0c38a`); вторая — `~/Projects/dv-hub/context/DV/Operations/Kanban/Kanban Board.md`,
где `context` — **git-сабмодуль** на репозиторий dv-project (`.gitmodules`); файлы
отличаются только отметкой авто-пересборки (13:08 против 13:14). Скрипты идентичны.

**Третий канбан в контуре — по факту:** в волте свой — `07-Runbooks/ecosystem-kanban-runbook.md`,
`tools/ecosystem-map/registry.json` (35 карточек ECO-NNN, lifecycle IDEA→…→RETIRED) и
`TASKS.md` (оперативные T-NNN); спека `docs/specs/ecosystem-registry.md` — `status: proposed`.

сущность, к ресёрчу отношения не имеет, но при сведении «куда свести» её надо назвать.
