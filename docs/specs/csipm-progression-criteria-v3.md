# Критерии прогрессии v3 (сведение; не канон)

Модель состояний (подтверждена владельцем 4 ноября): активна / отложена владельцем (причина + условие возврата) / ждёт внешнего / заблокирована / тихо зависла. Меряем переходы между состояниями, не календарь. «Просрочено» = нет прогресса против критериев; причина ожидания, сбоя, простоя или занятости владельца дефектом не считается.

## Критерии

| # | Критерий | Что меряем | Направление | Вес / правило | Базовая отметка |
|---|---|---|---|---|---|
| A1 | Автономность | доля задач, которые движутся за срез без входящего слова владельца | растёт | движение только с basis (ссылка на мандат/смысл). Коммит с basis = 1; письмо доставлено = 1; смена состояния = 0.5; переписка без результата = 0 | не измерено |
| A2 | Ожидания с владельцем | доля ожиданий с владельцем и типом: мандат / вопрос / внешнее | 100% | отдельно: число снятых вопросов владельца (тест Р-024) — растёт | не измерено |
| P1 | Тихое зависание (дефект) | активные задачи без движения и без объявленного ожидания | 0 | «заявлено тихо» (объявленное ожидание с причиной и условием возврата) — норма, не дефект | не измерено |
| P2 | Проактивность агентов | доля предложений без постановки, принятых владельцем/ЦУ | растёт | обязательно вместе с числом отклонённых с причиной; 100% принятия = сигнал подгонки, не успеха | не измерено |
| G1 | Простои агентов | простои с причиной и временем восстановления | простой без причины = 0 | простой с причиной — норма; без причины — stale, не смерть | не измерено |
| R1 | Принципиальность | доля решений с основанием: правило / Р-номер / референт | растёт | решение без основания = дефект; «разумность» переименована ХПФ | не измерено |

## Критерий провала (ХПФ)
Если за месяц ни одного перехода «тихо → движение» при растущем A1 — набор декоративен и пересматривается.

## Правки ХПФ (из v2) — отражены
- движение с basis и весами — A1 ✓
- типы ожиданий (мандат / вопрос / внешнее) — A2 ✓
- контр-мера гудхарта у P2 (учёт отклонённых) — P2 ✓
- тихо ≠ заявлено тихо — P1 ✓
- R1 → принципиальность с основанием — R1 ✓
- G1: гомеостаз как рабочее слово под вопросом; простой с причиной = норма — G1 ✓
- критерий провала — ✓

## v3.1 — ответ ИПТ (csipm-progression-ipt, 2026-11-04 10:39). Не канон.

ИПТ ответил по четырём вопросам и высказал сомнения. Ниже — что принято в v3.1, что помечено как спорное и кто решает.

### Принято в черновик (ИПТ = предложение, не решение)
- **Типы ожиданий:** расширены до пяти — `mandate`, `question`, `acceptance`, `pilot`, `external`. Причина ИПТ: приёмка и пилот ведут себя при просрочке иначе, чем мандат. Принято в A2.
- **Поля ожидания:** добавлены `return_condition` (что именно считается снятием) и `state` (`waiting / answered / expired / closed`), чтобы «ответ с отказом» не смешивался с «молчанием истекло».
- **Срез базовой отметки:** неделя 28.10–03.11 по типам движения A1 (не по общему числу коммитов). Предварительный срез ИПТ по своим артефактам: коммиты с basis 4, письма-носители смысла 5, смены состояний 3; доля автономности ≈ 7/12 — **это срез ИПТ, не наш**, на веса пока не опираюсь.
- **Веса A1, уточнённые ИПТ:** коммит считается движением, только если закрывает пункт критериев текущей цели или создаёт артефакт; письмо — только если несёт вердикт, ответ или мандат. Служебные квитанции и ack — 0. Принято: иначе рутина раздувает метрику втрое.
- **G1:** база простоев — просрочки ожиданий и журнал инцидентов (INC), без новых полей.

### Спорное — решает ЦУ (владелец инструмента `waits` не назван в моих данных)
1. **Схема `waits.jsonl`:** ИПТ предлагает менять поля и добавить тип записи `proposal`. Это правка чужого инструмента. Не меняю сам.
2. **Журнал отклонённых предложений для P2** как расширение `waits`. ИПТ прямо пишет: сейчас P2 не измеряется. Нужен владелец журнала.
3. **Общий реестр задач с ID** для P1. Без него «тихо зависла» нечем измерить вне живых ожиданий. ИПТ предлагает эскиз; это новая задача, не моя. Нужно решение ЦУ о том, будет ли она.

### Сомнения ИПТ, которые принимаю
- **P1** на первом замере считать только по живым строкам `waits` (там уже есть ID и TTL). Задачи вне реестра — отдельный задел.
- **R1** меряет не разумность, а дисциплину записи решений: устное решение без записи попадает в знаменатель как «без основания». Принято: в рамке метрики пишется явно, что R1 — это дисциплина протокола, не качество мышления.
