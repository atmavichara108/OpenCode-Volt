# Операция «Гомеостаз»: один организм, не куски

## 0. Диагноз (почему «расклеивается раз в два дня»)

Дефекты дня — не причина, а симптомы одной болезни: **подсистемы существуют
по отдельности, и связь между ними держится на памяти и сообразительности
нейронок**, которые по определению глючат и забывают. Конкретные следствия:
мандат без записи-ожидания (невидим для экрана), строка без билета (нечем
проверить), зов без различения «молчит/не может ответить», сторож,
повторяющий один дрейф 371 тысяч раз, две просроченные заявки вне реестра.

Принцип операции: **каждая связь — программа, каждая программа — одна
ответственность, каждая ответственность — проверяемый инвариант.**

## 1. Подсистемы: что за что отвечает (одна на роль)

| # | Подсистема | Единственная роль | Инвариант (проверяемый) |
|---|---|---|---|
| 1 | Реестр адресов | адресация всех линий | send в незарегистрированный sid = отказ; строка без агента/дома/зоны = дефект |
| 2 | Почта (ship-mail) | единственный транспорт | письмо без разделов/ссылки = отказ (линт); факт снятия на диске; зов несёт id письма |
| 3 | Зов (wake + таймеры) | единственный будильник | зов только потребляющей линии; каждый случай в журнале; интервал из таймера, не из головы |
| 4 | Ожидания (waits) | единственный учёт «жду» | каждая ждущая строка = sid + что + срок по природе события + return-условие (билет) |
| 5 | Живое состояние (persist) | единственный доказательный слой | слово владельца дословно; bootstrap стартом хода; решение без persist-записи = нет решения |
| 6 | Следопыт (follower) | единственный обход продукта | портрет очереди из реестров; метка строки; расхождение печати и пересчёта = флаг |
| 7 | Книга родства (lineage) | единственный учёт зон/веток | claim вне реестра = отказ; TTL истекает сам; мерж не удаляет строк |
| 8 | Сторож (watch+drift) | единственный детектор дрейфа | повтор подавлен; каждый инцидент несёт sid+ref+evidence |
| 9 | Коп сессий (session-cop) | единственный сверщик реестра и API | «мёртв» ≠ «нет в выборке»; агент/дом совпадают с реестром |
| 10 | Пробы (probe, probe-rotator) | здоровье моделей | каждый отказ классами (троттлинг/исчерпание/сеть) |
| 11 | Ключник (key-rotator) | ключи провайдеров | значение только через Ворота; в чат не попадает |
| 12 | Формы-сторожа (garbage-guard, линты, frontmatter) | фильтр записи | смесь алфавитов/иероглифы/нет раздела = отказ |
| 13 | Цель (goal + sidecar) | единственный приоритет | у сессии есть активная цель; WIP один; критерии измеримы |
| 14 | Ворота (owner-gate) | единственный путь секретов | секрет = файл 600, не переписка |
| 15 | Журнал команд (cmdlog) | данные экономии | каждая команда с sid/rc; счётчик кормится из журнала |

## 2. Связи (кто на кого опирается)

```
                 ┌───────────── ЦЕЛЬ (приоритет 0) ─────────────┐
                 │                                              │
   РЕЕСТР ──► ПОЧТА ──► ЗОВ ──► линии ──► ответы ──► ОЖИДАНИЯ ──► ЭКРАН
     │          │          │                    │                  │
     │          │          └─ журнал всех случаев (проверяемо)     │
     │          └─ линт fail-closed ──────────────────────────────►│
     │                                                        ┌───┴────┐
     ▼                                                        ▼        ▼
   Книга зон ◄──claims── линии                          ПЕРСИСТ   СЛЕДОПЫТ
     │ TTL/истечение                                      (доказательства) (портрет очереди)
     ▼                                                        │        │
   СТОРОЖ ──оси дрейфа──► инциденты ──► строки зеркала ◄───────┘        │
     ▲                        ▲                                     │
     └── КОП (реестр vs API) ──┴── ПРОБЫ (модели) ──► КЛЮЧНИК ──► ВОРОТА ──► владелец
```

Правило чтения: **почта без реестра не адресует; экран без ожиданий молчит;
ожидание без срока по природе события врёт; зов без журнала неучитываем;
сторож без подавления шумит; коп без различения мёртвых и выборки лжёт.**

## 3. Что уже сделано (фундамент, не с нуля)

- почта: зов только потребляющей линии (Р-116), факт снятия на диске, id в зове;
- срок строки по природе события (интервал как у хозяина: 10 минут = таймер);
- сторож: повтор подавлен, раздутый журнал заархивирован (76МБ → 1.5МБ);
- claims: две просроченные заявки истекли;
- мандаты дня → записи-ожиданий (экран видит все);
- встраивания на нашем ключе; ступень 4 под гейтом безопасности.

## 4. Декомпозиция (задачи → ведомства)

| # | Задача | Ведомство | DoD (измеримый) |
|---|---|---|---|
| У-1 | Fail-closed claim: заявка вне реестра = отказ; авто-истечение по TTL | ИЦ | тест: claim от нерегистрированного sid не проходит; просроченный claim истекает сам |
| У-2 | Коп: различать «мёртв» и «нет в выборке»; сверка агент/дом по реестру | ИЦ | отчёт копа: мёртвые/живые/неизвестные разделены; лишних 0 |
| У-3 | Экран ожиданий: срок по природе события (event_at), шесть видов триажа | Школа + ИЦ | на срезе: ложных «просрочено» 0; строк без билета 0 |
| У-4 | Почта единообразна для всех: линт + форма + ack-факт + зов-id в одном каноне | ИЦ + ЦУ | любая линия читает канон из слоя и работает без исключений |
| У-5 | Поднять все жизненные центры одним расписанием (таймеры: зов, пробы, объезд, сторож) | ИЦ | один список таймеров; каждый со своей зоной; падение одного не глушит другие |
| У-6 | Следопыт ↔ реестр ↔ почта: метка строки из источников, дубль-детект | ИЦ + Школа | «БЕЗ МЕТКИ 0» на живых; повтор вопроса ловится строкой |
| У-7 | Идемпотентность: повторы команд/операций без побочных эффектов | ИЦ | тесты: двойной feed/ack/send не создают дублей |
| У-8 | Канон-operation «гомеостаз» в слои: цель 0, инварианты, процедура | ЦУ | раздел в инструкции агентов + в реестре решений |
| У-9 | Зеркало суточное: строка дня несёт и жизненные центры, и дефекты с классом | Школа | строка 07.11+ в новом формате |
| У-10 | Проверка хозяином: он видит каждую сессию — по его слову корректируем | ЦУ | хозяин подтверждает: «не расклеивается» две ночи подряд |

## 5. Критерии цели (жёсткие, измеримые)

1. **Целостность адресации:** 0 отправок в незарегистрированный sid; 0 строк
   реестра без агента/дома/зоны.
2. **Целостность учёта:** 0 мандатов без записи-ожидания; 0 строк без билета
   (return-условия); 0 строк без срока по природе события.
3. **Целостность доказательств:** 100% слов владельца дословно на диске; 0
   решений без persist-записи.
4. **Целостность канала:** 0 писем без линта; 0 зовов без журневой записи;
   0 зовов непотребляющим линиям.
5. **Целостность сторожей:** 0 повторов в журнале (подавлены); 0 заявок вне
   реестра; 0 неистёкших просроченных claims.
6. **Идемпотентность:** повтор любой операции не меняет состояние (тесты).
7. **Устойчивость:** падение одной подсистемы не глушит остальные (таймеры
   независимы); каждая имеет проверку.
8. **Ночь без хозяина:** система работает и ремонтируется сама; хозяин видит
   зеркало, а не аварию.

**Kill-условие:** если через 3 дня цель 0 не сдвинулась по критериям 1-5 —
   остановка и пересмотр декомпозиции (не «ещё немного try»).

Наименования ведомств в декомпозиции — канон peer-registry: «ИС» в ранних
черновиках = Инженерный центр (ИЦ), ses_ece7b76c8ffeOkYZqZe38QbTVx.

## 6. Канонические цели — проверяемо (для пингера, не для памяти)

Записаны на диск (goal.json + sidecar сессии, поле `checks`); пингер любой линии
сверяет по ним. Общий дедлайн: **8 часов от старта операции (до 06:36 08.11)** —
слово владельца: «8 часов максимум». Каденция пинга: 30 минут до закрытия всех
целей (слово владельца через AllIs Maya).

| Цель | Проверка (чем закрывается) |
|---|---|
| 1. Адресация целостна | срез отправок: 0 получателей вне peer-registry; 0 строк реестра без агента/каталога/зоны |
| 2. Учёт целостен | waits.jsonl: 0 строк без билета; 0 без срока по природе события; счётчик «ответ-без-пришивки» = 0 |
| 3. Доказательства целостны | persist: 100% слов владельца дословно; 0 решений без persist-записи |
| 4. Канал целостен | 0 писем без линта; 0 зовов без записи в журнале; 0 зовов непотребляющим |
| 5. Сторожа целостны | 0 повторов в журнале; 0 активных claims вне реестра; 0 неистёкших просроченных claims |
| 6. Идемпотентность | тесты: двойной feed/ack/send без дублей |
| 7. Устойчивость | падение одного таймера не глушит остальные |
| 8. Ночь без хозяина | ночной прогон без вмешательства; подтверждение владельца «не расклеивается» |
