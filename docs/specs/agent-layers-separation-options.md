# Разделение агентских слоёв — варианты с обоснованием

Запрос владельца (Р-062, basis: quoted): «давай разберём этот вопрос раз и навсегда,
жду варианты с обоснованием и рекомендациями».

## 1. Факты (evidence, не память)

1. **Два движка — не копия.** Слово владельца (Р-049): «это 2 движка - разные сдк
   но м код это форк опенкод десктоп - отсюда и гонка». `.mcode` —
   самостоятельный агентский слой, не зеркало.
2. **Механика переноса (по коду движка):** `UPSTREAM_PROJECT_DIR = ".opencode"` —
   константа в `app.asar`; при старте проекта переносятся только элементы,
   **отсутствующие** в `.mcode`; при коллизии — `"left in place"` (не
   перезаписывает). За всю историю лога — 2 переноса (06.10, 30.10), инкрементально.
3. **Глобальный слой один физически:** `~/dotfiles/opencode-global/.config/opencode`;
   `~/.config/mcode` — симлинк на него; 32 primary-агента видны обоим движкам
   (проверено верификатором). [проверить: параллельно существует реальный каталог
   `~/.config/opencode` с пересекающимися именами — какому движку какой путь читается,
   уточнить до канонизации.]
4. **Инцидент 30.10 (00:08):** покрытие имён было нарушено → запустился перенос в
   окне загрузки сессий → гонка ~1.7с → 226× `ConfigInvalidError`. Не баг движка,
   а следствие сосуществования (Р-049/Р-052).
5. **Двойные копии** — постоянное условие (docs/engines.md, 7240a81): правило
   `имена(.mcode) ⊇ имена(.opencode)` → движку нечего переносить → `.opencode`
   неприкосновенен; проверка — командой `comm` по agent/command/skills/tools.
6. Миграция-стэш (удаления трекаемых `.opencode`) — объявлена НЕ-каноном (Р-049);
   восстановленные копии остаются; удаления не коммитятся.

## 2. Варианты

| | Суть | Плюсы | Минусы |
|---|---|---|---|
| **A. Статус-кво формализован** | оба слоя самостоятельны (как сейчас); зафиксировать содержательную карту «какая версия агента/команды в каком слое и кто её ведёт» + сторож покрытия имён | не ломает работающее; уважает слово владельца; лечит причину инцидента | требует регулярного ведения карты; два места правки по умолчанию остаются |
| **B. Единый источник + зеркало** | `.opencode` = SSOT, `.mcode` = результат переноса (что движок фактически и делает) | одна правка; нет двойного ведения | противоречит слову владельца («самостоятельный слой»); возвращает соблазн «убрать лишнее»; теряет M Code-специфику (свои версии агентов — канон её движка) |
| **C. Функциональное разделение** | `.opencode` — клиентский/разработческий слой OpenCode-контура (конфиги/общие скилы/общие тулы); `.mcode` — движковый слой M Code (его версии агентов/команд/скиллов); общий глобал — один (симлинк); связь — реестр имён + машиная проверка покрытия | каждому движку — своё; масштабируется (гейт = реестр, автопроверка); перенос остаётся страховкой, не гейтом | требует первого содержательного решения владельца (что куда относится) |
| **D. Полная изоляция** | запрет переноса; слои ведут себя независимо | нет гонок в принципе | двойная работа размножается; дрейф двух реестров агентов; потеря единства флота |

## 3. Рекомендация ЦУ — **C, с элементами A**

1. **C как каркас:** функциональное разделение зафиксировано содержательно (разделение
   слоёв — не «два одинаковых списка», а «своё у своего движка» + общий глобал одним
   путём). Прямо реализует твою рамку «всё — объект»: у каждого объекта слоя — свой
   класс-владелец.
2. **A как страховка:** машиная проверка покрытия имён (`comm`) + сторож дрейфа в
   канве ЦСПИМ = симптом «две половины конфига в полёте» не возникает молча.
3. Перенос в `.mcode` при старте остаётся **штатной механикой**, а не поводом для
   тревоги: при соблюдении покрытия он переносит НОЛЬ элементов (это и делает
   инцидент невозможным по построению, а не по дисциплине).
4. Именование/активация агентов — по-прежнему через реестр имён (УАС); активационная
   копия ложится в слой своего движка; состав заносится в карту.

## 4. Что нужно от владельца (одно слово + карта)

1. Вариант: **C (рекомендация) / A / B / D**.
2. Содержательная карта старта: какие агенты/команды/скилы относятся к «движковому»
   слою M Code, а какие — к к слою OpenCode (первый заход сделает УАС по факту
   активаций, черновик — на апрув).
3. [проверить] пулу глобальных путей (`~/.config/opencode` vs симлинк) — до
   канонизации — верификатору.

## 5. Что делается сразу после слова

- Р-запись канона; карта слоёв — в реестр имён/манифестов (УАС); comm-проверка —
   в сторож недели (R-052 уже требует); спека отделов/манифестов — правятся одной
  строкой «слой противного».
