## S1. Цель

Первый живой тест настоящего конфликта писателей: две сессии одновременно
пишут в общий append-файл; Git Freed (freed.py + git-freed агент) должен
обнаружить гонку, не дать потерять ни одну запись и корректно остановиться
на реальном конфликте.

Это шаг 3 роадмепа; после его PASS — отложенный багфикс модели peer-comms.

## S2. Материалы

- `tools/git-agent/freed.py` (detect/check/lease-list, exit 0/1/2).
- Агент `.opencode/agents/git-freed.md` (рутина/стоп-лист).
- Граф idea-graph (validations) — уже подключён к detect.

## S3. Сценарий (полный цикл)

1. **Подготовка**: тестовый песок в `04-Memory/idea-graph/race-test/`
   (узлы/рёбра не трогаем — только песочница: `race-nodes.jsonl`).
   Две сессии получают одинаковую инструкцию по ходу.
2. **Ход 1 — нормальная запись**: сессии пишут по одному узлу по очереди
   (handshake-квота: пишет один, второй ждёт). После каждого — freed.py detect
   + validate.mjs. Ожидание: ok 0 warnings.
3. **Ход 2 — гонка**: обе пишут одновременно (без квоты, 5-10 узлов каждая).
   Свободный scан сразу после: freed.py должен позволить появиться WARN (2
   писателя общего поля), validator поймает дубли ID/некорректный JSON если есть.
4. **Ход 3 — разрешение**: по протоколу freed.py конфликт — append-new-ID
   (без перезаписи прошлых строк), повторный validate; дубль-ID должен быть
   обнаружен и отп almonds «первый живой кейс», как это уже было с e-0177.
5. **Итог**: небольшой отчёт: что ожидали/что произошло diffs/детектор-логи.

## S4. Что тест должен ДОКАЗАТЬ (acceptance)

1. Ни один узел не потерян (count до = count после, дубли явно именованные).
2. freed.py WARN на гонке; validate/ mint-скрипт надёжно отлавливает битое.
3. Так как конфликт один — наш уже бывший (e-0177) — детектор должен был бы
   его поймать, если бы запускался между ходами.
4. Проверки идут read-only, ничего из канона не перемещается.

## S5. Границы

- Не открывать новых процессов OpenCode (стоп-уровень: 2 существующие сессии).
- Не разворачивать узлы в main; тестовая директория может быть удалена
  после отчёта.
- Не трогать реальный nodes.jsonl (граф-писатель — igraphv2).
