## S1. Роль органа

Git Freed — именованная способность владения деревом: протокол
commit/scope/lease/conflict как контракт, а не привычка. Девиз: высвобожденный
потенциал, который томился, пока его не призвали. Гит-агент не хозяин смыслов —
он упаковывает, стережёт и исполняет рутину.

Синтез поглощённого (эволюция через жертвование):
- `tools/tree-cop` → глаза (детект грязи/гонки/чужого WIP)
- `tools/peers/peer_lease.py` → руки lease (заявка/hold/TTL/release)
- `main-protector.ts` → щит (гейт main)
- `02-Methods/git-worktree-isolation` → исполняемый протокол веток
- pre-commit хуки → шаги цепочки гейтов

## S2. Раскладка (Q2 = гибрид)

- **Детектор (kernel-слой):** дешёвый read-only анализ: git status, кто держит
  файлы (claims.jsonl peer-реестра), чей scope, гонка писателей в один файл.
  Размещение в dotfiles второй итерацией (плагин-хук или скрипт-вызов).
- **Исполнение (проектный слой):** git-операции живут в репо хозяина сюжета.
  Первый контур — волт (`tools/git-agent/` или агент git-freed в `.opencode/`).

## S3. Автономия (Q3 = рутина без спроса)

**Рутина (исполняет сам):**
1. `git add <пути собственного scope>` — только пути из подтверждённого scope;
2. `git commit` с message по протоколу;
3. `git tag` (релизные вехи по протоколу);
4. `git push` в **свою** `task/*`-ветку;
5. `git worktree/branch` создание по политике AGENTS;
6. lease: claim/release по heartbeat.

**Approval требуется (жёсткий стоп-лист):**
- конфликт контента (не гонка формата, а разные правки одного куска);
- push в чужие ветки / merge / rebase чужих коммитов;
- удаление файлов, не принадлежащих scope;
- перенос чужих незакоммиченных правок (stash-foreign только по явной команде);
- main/master — никогда (щит).

## S4. Протокол commit-цепочки

scope → detekt (грязь/гонка/lease) → stage своих → гейты (ветка, pre-commit,
валидатор графа если тронут idea-graph) → commit → (tag) → push своей ветки →
отчёт одной строкой + запись события.

События (детект гонки, эскалация, релизный тег) — append-only узлы
в общий граф (graph=stream/event), с provenance.

## S5. Общая зона и append-only поля (паттерн, не список имён)

> **Правка 2026-10-07 (вердикт B9, scope sysop):** белый список точных имён
> (`nodes/edges/protocol.jsonl` в корне `04-Memory/idea-graph/`) не распознаёт
> гонку в подкаталогах — тест B9 в песочнице `race-test/` прошёл мимо детектора
> (`common_field_dirty=[]`, `warnings=[]`). Контракт меняется на **шаблон**:
>
> - общая зона — каталог `04-Memory/idea-graph/` **рекурсивно**;
> - общее append-only поле — **любой** `*.jsonl` внутри общей зоны (включая
>   подкаталоги и песочницы вида `race-test/`, `generated/`);
> - **исключение (архив):** пути, содержащие компонент `archive/` или
>   `_archive/`, не считаются живым полем (архивная копия). Код и спека
>   должны совпадать: исключаются **оба** варианта написания;
> - грязный (`M`/`??`/`A`) общий `*.jsonl` → WARN вида
>   `common-field:<относительный путь>`, независимо от имени файла;
> - список имён в корне больше не используется; прод-поведение сохраняется
>   (три корневых файла по-прежнему дают WARN).

Дополнительно (валидатор графа): `tools/idea-graph/validate.mjs` должен
принимать **явный путь/набор файлов** вместо жёсткого прод-каталога, чтобы
тест гонки валидировался в песочнице. Для каталога, отличного от прод-графа,
пороги v2 (90 узлов / 120 рёбер) и проверка архива v1 не применяются —
проверяются структура, дубли id, типы, ссылки, парсинг JSONL. Прод-запуск
без аргументов остаётся неизменным.

## S6. Conflict-стратегия

1. Гонка по append-only файлу (JSONL) → auto-merge построчно (разные хвосты).
2. Чужая WIP мешает → stash-foreign (по tree-cop), работа, pop на ветке хозяина.
3. Реальный content-конфликт → ЭСКАЛАЦИЯ: один вопрос с вариантами.
4. Конфликт-маркеры/MERGE_HEAD → суффикс `-conflict` ветки, разбор только там.

## S7. Границы (Maya-boundary включена)

- Имя и сообщения коммитов — нейтральные (Git Freed, не «Вельзевул коммитит»).
- Кодексы приложений и prod-конфиги — не трогает.
- Смысл коммита = владелец сюжета; Git Freed не придумывает, что коммитить.
- Коммуникация ≠ авторизация: отчёт Git Freed ≠ право на следующее действие.

## S8. Первый контур (волт) — Deliverables

1. Детект-скрипт `tools/git-agent/freed.py` (или `.mjs`): status/owner/гонка/lease
   — детерминированный, exit-коды, без LLM внутри (данные; выводы — агент).
2. Агент `git-freed` в `.opencode/agents/` с правилами S3 или skill-протокол —
   разметку выбирает реализация.
3. Интеграция с claims.jsonl (hello/lease/release) — контракт peer-comms.
4. Смок: живой тест на настоящей гонке двух параллельных сессий (у нас их
   двое — librarian и idea-graph v2) + verifier PASS.

### S8.1 Приёмка детектора после B9 (обязательно)

Детектор обязан давать `warning` (`check` → rc=1) в двух случаях:

1. **Одновременная запись** в общий append-only `*.jsonl` (два живых писателя
   общего поля) — независимо от того, в корне зоны файл или в подкаталоге
   (`race-test/` тоже).
2. **Дубль `id`** внутри одного общего `*.jsonl` (конфликтный кейс
   append-new-ID) — с указанием пути и значения дубля.

Exit-коды сохраняются: `0` ok, `1` warn, `2` blocked. Детекция — детерминированная,
zero-LLM. Прод-поведение (три корневых файла) не регрессирует.

Повторный прогон B9 на существующих артефактах `04-Memory/idea-graph/race-test/`
(прод-граф не трогать): детектор обязан поймать и гонку, и дубль `race-a-101`.

## S9. Последующие контуры

- dotfiles: kernel-детектор как глобальный плагин + перенос протокола.
- остальные репо: adoption по одному, gate = успешный контур dotfiles.
- Критерии зрелости: 0 случайных чужих-коммитов за 2 недели; 0 ручных «сверь diff»;
  эскалаций меньше, чем автослияний append-only.
