# Черновик критериев прогрессии (не канон)

Модель состояний вместо дней подтверждена владельцем: активна / отложена владельцем (причина + условие возврата) / ждёт внешнего / заблокирована / тихо зависла (активна, без движения и без объявленного ожидания). Критерии ниже меряют переходы между этими состояниями, а не календарь.

| # | Критерий | Что меряем | Направление | Источник данных | Базовая отметка |
|---|---|---|---|---|---|
| A1 | Автономность | доля задач, которые движутся за срез без входящего слова владельца | растёт | коммиты, письма, ожидания по задачам | не измерено |
| A2 | Ожидания с владельцем | доля ожиданий с назначенным владельцем и условием возврата | 100% | waits.jsonl | не измерено |
| P1 | Тихое зависание | число задач в активном состоянии без движения и без объявленного ожидания | 0 | реестры + события | не измерено |
| P2 | Проактивность агентов | доля предложений, выдвинутых агентом без постановки и принятых | растёт | письма, реестр решений | не измерено |
| G1 | Гомеостаз (простои) | доля простоев агентов с причиной и временем восстановления | 100% (простой без причины = дефект) | журналы сбоев, watch-logs | не измерено |
| R1 | Разумность | доля решений, принятых по зафиксированным правилам без вопроса владельцу | растёт, каждое решение проверяемо | реестр решений, правила Р-024 | не измерено |

## Открытые вопросы к обсуждению
1. Что считать «движением» (коммит, письмо, смена состояния) — и нужен ли вес у разных видов движения?
2. Срок среза (неделя?) и как учитывать периоды, когда владелец сознательно не занимается проектом (состояние «отложена владельцем» исключает из знаменателя или нет?).
3. Как отделить «агент сам выдвинул предложение» от «агент выполнил постановку».
4. Кто ведёт учёт критериев — ЦСПиМ (проекция) и откуда берётся базовая отметка.

Черновик ждёт обсуждения с ИПТ (исследование вариантов измерения) и ХПФ (какие концепты ложатся и реализуемы), совместно с ИЦ. Итог — только словом владельца через ЦУ.

## Версия 2 — правки ХПФ (ответ csipm-progression-hpf-reply, 2026-11-04). Не канон.

Вердикт ХПФ: критерии ложатся на доктрину с тремя обязательными правками (basis у движения; типы ожиданий; контр-мера гудхарта у P2/R1). Ниже — правки и остальные замечания ХПФ, которые внесены в черновик.

| # | Было | Стало (предложение) | Основание (ХПФ) |
|---|---|---|---|
| A1 | доля задач, движущихся без слова владельца | движение считается только при наличии basis (ссылка на мандат/смысл); веса: коммит с basis = 1; письмо доставлено = 1; смена состояния = 0.5; переписка без результата = 0 | «движение» без веса = переписка ради метрики; без basis = шум |
| A2 | доля ожиданий с владельцем | у каждого ожидания — ТИП: (а) мандат (владелец обязан дать слово), (б) вопрос (владелец отвечает на неопределённость), (в) внешнее (не владелец). Отдельно — метрика «снятые вопросы владельца» (тест Р-024) | ожидание, смешанное в процент, даёт «владелец должен» + «мир должен» в одной цифре |
| P1 | тихое зависание = активна без движения и без ожидания | разделить: «тихо» (дефект: нет владельца ожидания) и «заявлено тихо» (объявленное ожидание с причиной и условием возврата — норма). Зависание ≠ смерть: меряем движение, не пульс | статус «занят» ≠ «мёртв» |
| P2 | доля принятых предложений агента | обязательная контр-мера: учёт отклонённых предложений с причиной. 100% принятия = сигнал подгонки, а не доказательство точности | гудхарт: поддакиватель имеет 100% принятия |
| R1 | «разумность»: решения по правилам без вопроса владельцу | переименовать в «принципиальность»: доля решений с основанием (правило / Р-номер / референт). Решение без референта = привычка, не разумность | «разумное» в доктрине = по смыслу с правом отказа, не по привычке |
| G1 | гомеостаз: простой с причиной | простой с причиной — норма; простой без причины — stale (не смерть). Слово «гомеостаз» как рабочее под вопросом: аналогия организма, не буква Корабля | ХПФ: биология удобна, но Корабль ≠ организм |
| — | критерия провала не было | добавлен: если за месяц ноль переходов «тихо → движение» при растущем A1 — набор декоративен | доктринальный стандарт честности (протиповречие как топливо, критерий провала заранее) |

## Что ИПТ/ИЦ нужно уточнить технически
- поля ожидания: владелец, тип, условие возврата (сейчас в waits.jsonl есть ref и TTL, типа нет);
- веса движения и источник basis;
- базовая отметка: срез за прошлый период (до введения критериев);
- журнал отклонённых предложений для P2 (сейчас учёта нет).
